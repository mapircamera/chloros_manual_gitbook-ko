# 이미지를 전체 화면으로 열기

<figure><img src="../.gitbook/assets/image (34).png" alt=""><figcaption><p>이미지를 전체 화면으로 열면, 오른쪽 상단에 레이어 선택기가 표시됩니다</p></figcaption></figure>

Chloros 이미지 뷰어는 이미지를 보고, 검사하고, 측정하기 위한 전체 화면 인터페이스입니다. 이곳에서는 화면이 표시하는 늘어난 미리보기 대신, 채널별 DN, 반사율(%), 또는 W/m²/sr/nm 단위의 복사도 등 **실제 픽셀 값**을 확인할 수 있습니다.

## 이미지 뷰어 열기

### 파일 브라우저에서

1. **파일 브라우저** 탭<img src="../.gitbook/assets/icon_file-browser.JPG" alt="" data-size="line">을 엽니다.
2. [이미지 그리드](image-grid.md)에서 **썸네일**을 클릭합니다.
3. 이미지가 **이미지 뷰어** 탭에서 전체 화면으로 열립니다.

이미지는 그리드가 표시하던 제품에서 열립니다. 그리드가 `RAW (Reflectance)`로 설정되어 있다면, 해당 레이어로 이동하게 됩니다.

### 이미지 뷰어 사이드바 열기

왼쪽 사이드바에 있는 **이미지 뷰어** <img src="../.gitbook/assets/icon_image-viewer.JPG" alt="" data-size="line"> 아이콘을 클릭하면 분석 패널이 슬라이드 방식으로 펼쳐집니다. 이 패널에는 위에서 아래로 다음과 같은 항목이 포함되어 있습니다:

* 이미지 이름 및 카메라 모델
* **이미지 내보내기/저장** 버튼 (인덱스 또는 LUT가 활성화된 경우에만 표시됨)
* **인덱스**및**LUT** 선택 상자 및 인덱스 구성 패널 — [인덱스/LUT 샌드박스](index-lut-sandbox.md) 참조
* **커서 값** 패널: 채널별 판독값, 레이어 히스토그램 및 GSD 제어***

## 탐색 및 확대/축소

### 이미지 탐색

* **다음 이미지**: → 버튼 또는**→**(오른쪽 화살표) 키
* **이전 이미지**: ← 버튼 또는**←**(왼쪽 화살표) 키
* **특정 이미지로 이동**: 그리드로 돌아가 해당 썸네일을 클릭합니다

이미지 간을 이동할 때도 확대/축소 및 이동 설정이 유지되므로, 프레임의 동일한 부분을 유지한 채로 일련의 이미지를 차례로 살펴볼 수 있습니다.

### 확대/축소

확대/축소는 **마우스 휠**로 제어되며, 15% 단위로 커서를 기준으로 적용됩니다. 즉, 포인터 아래의 지점이 포인터 아래에 그대로 유지됩니다. 확대/축소 범위는 이미지와 창 크기에 의해 제한됩니다. ‘창에 맞추기’ 상태보다 더 축소할 수는 없으며, 상한은 이미지의 기본 해상도로 설정됩니다.

전체 화면 뷰어에는 전용 확대/축소 키가 없습니다. (그리드 모드에서는 **Ctrl + `+` / `−`**를 사용하여 썸네일 크기를 조정할 수 있습니다. 이는 별도의 제어 기능입니다.)

### 확대 시 이동

이미지 위에서 마우스 왼쪽 버튼을 클릭한 상태로 드래그하세요. 이동 범위는 제한되어 있어 이미지를 화면 밖으로 드래그할 수 없습니다.

### 고배율에서의 픽셀 단위 검사

유효 배율이 **60×**를 초과하면, Chloros는 커서 아래에 표시된 개별 픽셀 주위에 하이라이트 상자를 그리고 그 옆에 부동 값을 표시합니다.

“유효” 배율은 GSD 블록 크기를 고려합니다. 블록 크기가 8인 경우, 표시된 픽셀 하나가 이미 8 × 8 소스 픽셀을 차지하므로 60×가 아닌 7.5× 확대 시에 하이라이트가 나타납니다. 확대 배율을 임계값 이하로 줄이면 하이라이트가 사라집니다.

### 키보드 단축키

| 키                             | 위치       | 동작                              |
| ------------------------------- | ----------- | ----------------------------------- |
| **→**                           | 전체 화면 | 다음 이미지                          |
| **←**                           | 전체 화면 | 이전 이미지                      |
| **Ctrl + R**                    | 전체 화면 | 인덱스/LUT 샌드박스 재설정         |
| **Ctrl + `+`**/**Ctrl + `=`** | 격자 보기        | 더 큰 썸네일 (한 번 누를 때마다 4 픽셀씩)  |
| **Ctrl + `−`**                  | 격자 보기        | 더 작은 썸네일 (한 번 누를 때마다 4 픽셀씩) |***

## 커서 값

이미지 위로 커서를 이동하면 **커서 값** 패널에 해당 영역 아래에 있는 모든 채널의 값이 표시됩니다.

{% hint style="success" %}
**이 값들은 파일의 실제 수치입니다.** 화면상의 캔버스는 8비트로 확장된 미리보기이므로 이러한 값을 제공할 수 없으므로, Chloros은 실제 제품 파일에서 샘플을 추출하여 값을 표시합니다. 이것이 바로 12비트 RAW 프레임이 255를 초과하는 값을 표시하고, float32 라디언스 레이어가 물리적 단위를 표시하는 이유입니다.
{% endhint %}

### 열의 의미

패널은 현재 보고 있는 레이어에 따라 달라집니다:

| 현재 보고 있는 레이어              | 표시되는 열    | 참고 사항                                                                                           |
| ---------------------------------- | ---------------- | ----------------------------------------------------------------------------------------------- |
| 반사율                        | **DN**및**%** | 백분율은 해당 파일 고유의 척도를 기준으로 계산됩니다 — 아래 참조                                      |
| 복사도                           | **W/m²/sr/nm**   | 부동소수점 물리 값; 여기서는 DN이 의미가 없으므로 DN 열이 없음                           |
| 원본 / 디베이이어 처리 / 미리보기 / JPG    | **DN**           | 정수형 디지털 수치                                                                         |
| 32비트 반사율 백분율 내보내기 | **%**만       | 저장된 부동소수점 값은 DN이 아니므로, 이를 정수로 반올림하면 의미 없는 `0` 또는 `1`가 출력됩니다 |

각 행에는 사용자의 카메라 필터에 해당하는 채널 이름이 표시됩니다 — `Red / Green / NIR`는 RGN용, `Orange / Cyan / NIR`는 OCN용, `NIR / Green / Blue`는 NGB용, `Red / Green / Blue`는 RGB용이며, RE, NIR 및 모노 M3M 카메라용입니다. 각 레이블에는 인덱스 공식 편집기에서 사용되는 채널 원과 일치하는 색상 점이 표시되어 있습니다.

저장된 **인덱스 및 LUT** 이미지는 특별한 경우입니다. 이 이미지들은 스펙트럼 밴드 대신 컬러 맵 구성 요소를 포함하므로, 행에는 카메라의 필터 이름 대신 `Red / Green / Blue` (또는 단일 채널 인덱스 파일의 경우 `Index`)로 표시되며, 카메라의 필터 이름으로는 표시되지 않습니다.

샌드박스에서 인덱스가 활성화되면 채널 아래에 추가 행이 나타나 커서 위치의 **인덱스 값**을 표시하며, 인덱스 이름과 히스토그램의 마커와 일치하는 흰색 점이 함께 표시됩니다.

### 반사율(%)은 각 파일 고유의 척도를 사용합니다

{% hint style="warning" %}
**65535 = 100%라고 가정하지 마십시오.** Chloros는 생성된 카메라에 따라 서로 다른 척도로 반사율을 저장하며, 뷰어는 파일별로 올바른 척도를 적용합니다.
{% endhint %}

| 소스                  | 반사율 1.0에 해당하는 DN | 식별 방법                                                                                                                               |
| ----------------------- | ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| **LATTICE**(M3C / M3M) |**32768**                      | 모든 LATTICE 반사율 내보내기 파일에 XMP 태그 `Chloros:PixelScale=32768`가 기록됩니다. 2배의 헤드룸 덕분에 파일은 1.0을 초과하는 ρ 값을 클리핑 없이 포함할 수 있습니다 |
| **Survey3**|**65535**                      | Chloros XMP 스케일 태그 없음 — Survey3 보정 시 ρ × dtype-max를 기록하며 1.0에서 클리핑됨                                                               |

뷰어, 인덱스/LUT 샌드박스 및 인덱스 내보내기 기능은 모두 동일한 단일 구현을 통해 스케일을 처리하므로, 커서 위치에서 읽은 값은 인덱스 계산에 사용된 값과 동일합니다.

알아두면 좋은 두 가지 결과:

* **32비트 백분율**TIFF은 DN/65535를 부동소수점으로 저장하며,**8비트** PNG /JPG 내보내기는 DN × 255/65535를 저장합니다. 뷰어는 백분율을 표시하기 전에 두 값을 모두 원래 값으로 변환합니다.
* 복구할 수 없는 경우가 하나 있습니다: **8비트 원본 캡처 파일을**8비트 TIFF**형식으로 내보낸 경우**는 재조정되지 않고 0–255 범위로 잘리며, 의도적으로 스케일 태그가 포함되지 않습니다. 이러한 파일의 경우 패널은 백분율 열 없이 DN만 표시합니다. 이는 버그가 아닌 정확한 동작입니다.***

## 레이어 히스토그램

커서 행 아래에는 현재 보고 있는 레이어의 실시간 히스토그램이 **256개의 빈**단위로 표시됩니다. 기본적으로 `(R + 2G + B) / 4` 가중치를 적용한 하나의 통합 곡선이 그려지며, 이는 LATTICE 카메라 히스토그램이 사용하는 측정 공간과 동일합니다.**RGB**를 활성화하면 채널별 곡선이 채널 색상으로 표시되며, 중첩 부분도 가독성이 유지되도록 가산적으로 혼합됩니다. 모노 레이어는 항상 단일 곡선으로 표시됩니다.

가로축은 레이어 자체의 단위를 사용합니다:

| 레이어       | 축 단위  | 축 최대값                                               |
| ----------- | ---------- | ---------------------------------------------------------- |
| 반사율 | 백분율    | 125% — 제품의 헤드룸으로 인해 ρ가 1.0을 초과할 수 있음           |
| 복사도    | W/m²/sr/nm | 프레임 자체의 피크 값, 유의자릿수 2자리로 올림 |
| 8비트 데이터  | DN         | 255                                                        |
| 12비트 데이터 | DN         | 4095                                                       |
| 16비트 데이터 | DN         | 65535                                                      |

축이 DN 단위이고 이 세 가지 상한값 중 하나에 도달하면, Chloros는 사용자가 보고 있는 데이터의 비트 심도도 파악합니다.

히스토그램 위쪽에는 세 개의 버튼이 있습니다:

| 버튼     | 기본값 | 효과                                                                                                                                                                                                                                                                                   |
| ---------- | ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **커서** | 켜기      | 위 행에 표시된 정확한 값을 기준으로 히스토그램에 마커 선을 그립니다. 이를 통해 커서가 위치한 픽셀이 프레임의 분포에서 어디에 해당하는지 확인할 수 있습니다. ‘RGB’ 모드에서는 채널당 하나의 마커가 각 채널 고유 색상으로 표시되며, 그 외의 경우에는 합산된 값에 하나의 흰색 마커가 표시됩니다. |
| **INDEX**| 켜기      | 인덱스가 활성화된 동안에만 표시됩니다. 히스토그램을 소스 밴드에서**인덱스 값 분포**로 전환하며, 두 클립 임계값은 주황색 점선으로, 커서의 인덱스 값은 흰색 선으로 표시됩니다                                                          |
| **RGB**| Off     | 결합된 곡선에서 채널별 곡선으로 전환합니다. 모노 센서에서는 이 버튼에**MONO**라고 표시되며 비활성화됩니다. 표시할 채널이 하나뿐이기 때문입니다                                                                                                                                  |

히스토그램은 그 뒤에 있는 소스 픽셀이 아닌 **보이는 블록**을 기준으로 계산됩니다. GSD 블록 크기를 변경하면 분포가 재계산되므로, 히스토그램, 커서 마커 및 표시된 이미지가 항상 일치합니다.***

## GSD 블록 크기

패널 하단에는 **GSD (px)**제어 기능이 있습니다: 숫자 입력란,**1에서 256**까지 조절 가능한 슬라이더, 그리고**RESET** 버튼이 있습니다.

이 기능은 N × N 크기의 원본 픽셀 블록을 평균화하여 하나의 표시 픽셀로 합쳐, _표시되는_ 이미지의 해상도를 낮춥니다. `1`는 기본 해상도입니다.

* 이 설정은 **전체 화면 보기, 그리드 썸네일, 커서 표시값, 두 히스토그램** 등 이미지를 표시하는 모든 요소에 영향을 미치며, 모든 요소가 동일한 지상 해상도를 기준으로 일치합니다.
* 이는 **표시에만** 적용됩니다. 처리 및 내보내기에는 영향을 미치지 않습니다. 단 한 가지 예외가 있는데, 이는 의도된 것입니다: [인덱스/LUT 샌드박스](index-lut-sandbox.md)로 내보내면 현재 보고 있는 내용이 저장되므로 현재 블록 크기가 적용되며, 블록 크기가 1을 초과할 경우 내보내기 패널에서 경고가 표시됩니다.
* 이 값은 `viewer_display.gsd_bin`에 **프로젝트별**로 저장되므로, 프로그램을 닫았다가 다시 열어도 유지됩니다.
* 블록 크기가 1을 초과할 때마다 커서 표시창에는 소스 픽셀이 아닌 블록 값이 표시됩니다. 표시된 값은 커서 아래 블록의 평균값입니다.

{% hint style="info" %}
**왜 &quot;블록 크기&quot;이지 픽셀당 센티미터가 아닌가요?** cm/px 단위를 사용하려면 지면 위의 높이가 필요합니다. 단일 프레임의 EXIF에는 카메라가 향한 지형 위가 아닌 평균 해수면 위 높이를 나타내는 GPS 고도가 기록되므로, Chloros은 정확히 산출할 수 없는 지상 거리를 표시하지 않습니다. 소스 픽셀 단위의 블록 크기는 지상 샘플 거리(GSD)가 알려지지 않았을 때 MAPIR 클라우드 도구에서 사용하는 것과 동일한 대체 방법입니다.
{% endhint %}

## 볼 수 있는 이미지 유형

뷰어 우측 상단의 레이어 드롭다운 메뉴에는 현재 이미지의 모든 버전이 나열됩니다. 표시되는 항목은 카메라와 처리된 내용에 따라 달라집니다. 전체 목록과 드롭다운 메뉴의 작동 방식에 대해서는 [이미지 레이어](image-layers.md)를 참조하십시오.

### Survey3

* **JPG** — 카메라에서 생성한 미리보기 파일
* **RAW (Original)** — 원본 `.RAW` 데이터로, 표시를 위해 디베이어링 처리되었으며 보정되지 않음
* **RAW (Target)** — 보정 타겟이 포함된 것으로 식별된 프레임
* **RAW (반사율)** — 보정된 반사율 결과물 (65535 = ρ 1.0)
* **비네팅 보정**/**센서 응답** — 보정되지 않은 대체 결과물
* **화이트 밸런스** — 화이트 밸런스가 적용된 결과물
* **RAW (`<INDEX>` 인덱스)**및**`<INDEX>` LUT** — 계산된 인덱스 이미지

### LATTICE

LATTICE 캡처는 파이프라인의 레벨 이름이 포함된 동일한 드롭다운 메뉴를 사용합니다:

| 레이어                 | 포함된 내용                                                        |
| --------------------- | -------------------------------------------------------------------- |
| **RAW (원본)**    | 캡처된 소스 RAW 프레임                                     |
| **RAW (디베이어링 처리)**   | 선형 디베이어링 처리된 이미지                                           |
| **RAW (미리보기)**     | 디스플레이 미리보기 — 다중 스펙트럼 카메라용 가색 확장 |
| **화이트 밸런스 적용**    | RGB 마스터 카메라용 디스플레이 미리보기 (화이트 밸런스 + 감마)   |
| **RAW (방사도)**    | W/m²/sr/nm 단위의 Float32 스펙트럼 방사도                              |
| **RAW (반사율)** | uint16 반사율, 32768 = ρ 1.0                                    |

방사도 및 반사도는 다중 스펙트럼 전용입니다. RGB 마스터 카메라는 밴드별 방사계 측정이 지원되지 않으므로, 해당 레이어는 생성되지 않습니다.

***

## 인덱스 및 LUT 적용

사이드바에서 다중 스펙트럼 인덱스와 색상 룩업 테이블(LUT)을 적용하세요:

1. **이미지 뷰어**<img src="../.gitbook/assets/icon_image-viewer.JPG" alt="" data-size="line"> 사이드바를 엽니다.
2. **지수**를 선택합니다.
3. 카메라의 필터와 지수 공식을 선택한 다음, 채널 원을 공식의 슬롯으로 드래그합니다.
4. LUT를 추가하고 그라데이션, 임계값 및 클리핑 모드를 선택합니다.
5. 커서 위치의 값을 확인하고, **이미지 내보내기/저장**을 통해 결과를 저장합니다.

전체 단계별 안내는 [지수/LUT 샌드박스](index-lut-sandbox.md)를 참조하십시오.

## 문제 해결

### 이미지가 열리지 않는 경우

**가능한 원인**: 가져온 후 파일이 이동되거나 삭제된 경우; 파일이 제대로 저장되지 않은 경우; 매우 큰 이미지를 처리하기에 메모리가 부족한 경우.**해결 방법**:

1. 프로젝트의 출력 트리에서 해당 레이어의 파일이 여전히 존재하는지 확인하십시오.
2. 외부 뷰어에서 파일을 열어 파일이 손상되지 않았는지 확인하십시오.
3. 다른 응용 프로그램을 닫아 메모리를 확보하십시오.

### 이미지가 검은색, 흰색이거나 색상이 심하게 왜곡됨

**가능한 원인**: 디스플레이 스트레치에 처리할 데이터가 없음(거의 일정한 프레임); 비정상적인 값을 가진 float32 레이어; 유효한 데이터를 생성하지 못한 인덱스.**해결 방법**:

1. 커서 값을 확인하십시오 — 모든 채널의 값이 0이거나 0에 가까운 경우, 문제는 디스플레이가 아닌 데이터에 있습니다.
2. 히스토그램을 확인하십시오: 한쪽 끝에 단일 스파이크가 나타나면 프레임이 클리핑되었거나 비어 있음을 의미합니다.
3. 해당 레이어를 생성한 실행에 대한 처리 로그를 확인하십시오.

### 값이 잘못된 것처럼 보입니다

**가능한 원인**: 생각한 것과는 다른 레이어를 보고 있는 경우; 백분율(%) 값과 원시 DN 값을 비교하고 있는 경우; LATTICE 파일과 Survey3 파일을 동일한 나눗수로 나누어 비교하고 있는 경우.**해결 방법**:

1. 드롭다운 메뉴에서 선택한 레이어를 확인하십시오 — 패널의 단위는 레이어를 따릅니다
2. 반사율의 경우, 직접 DN을 나누지 말고 **%** 열을 사용하십시오. 반드시 나누어야 한다면 해당 파일의 `Chloros:PixelScale` 값을 사용하십시오(LATTICE의 경우 32768, 해당 값이 없으면 Survey3의 경우 65535).
3. GSD 블록 크기를 다시 1로 설정하십시오 — 1보다 크면 픽셀 값이 아닌 블록 평균값을 읽게 됩니다
4. 해당 프레임에 대해 반사율 보정이 실제로 실행되었는지 확인하십시오; 보정되지 않은 대체 제품(Sensor Response / Vignette Corrected)은 반사율이 아닙니다
