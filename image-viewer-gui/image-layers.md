# 이미지 레이어

이미지 뷰어 우측 상단에 있는 **레이어 드롭다운**을 사용하면, 뷰어를 벗어나지 않고도 현재 보고 있는 이미지의 모든 버전(원본 캡처 이미지부터 각 처리된 결과물, 계산된 인덱스 이미지에 이르기까지)을 전환할 수 있습니다.

## 이미지 레이어란 무엇인가요?

Chloros에서 “레이어”란 하나의 원본 이미지에 등록된 하나의 **결과 파일**을 의미합니다. 가져오기 과정을 통해 원본 파일을 확보하게 되며, 처리 과정을 거치면서 해당 실행에서 생성된 각 결과물마다 레이어가 추가됩니다. 내보낸 파일은 원본 파일 이름을 유지합니다. 제품을 식별하는 것은**폴더**이며, 레이어 이름은 Chloros가 해당 폴더에 부여한 레이블입니다.

## 레이어 목록

### 항상 존재하는 레이어

| 레이어 | 설명 |
| --- | --- |
| **JPG**(또는**PNG**/**TIFF**) | 캡처와 함께 들어온 기본 파일. Survey3는 모든 `.RAW` 옆에 `.JPG`를 가져옵니다. LATTICE 캡처는 PNG 또는 TIFF 디스플레이 미리보기를 포함합니다. 실제로 가져온 내용에 따라 라벨이 지정됩니다 |
| **RAW (원본)** | 보정 없이 디스플레이를 위해 디베이어링 처리된 소스 원본 프레임입니다. 가져오기 즉시 사용 가능 — 별도의 처리가 필요하지 않음 |

기본 파일이 원본 프레임인 LATTICE 캡처는 별도의 기본 항목이 없습니다: `RAW (Original)`가 이미 이를 포함하고 있습니다.

### Survey3 처리 결과물

| 레이어 | 기록 위치 | 생성 시점 |
| --- | --- | --- |
| **RAW (타겟)** | — | 이 프레임은 보정 타겟을 포함하는 것으로 식별됨 |
| **RAW (반사율)** | `Reflectance_Calibrated_Images/` | 이 프레임에서 반사율 보정이 성공적으로 실행됨 |
| **비네트 보정됨**| `Vignette_Corrected_Images/` | 해당 프레임은 반사율 보정을 수행할 수 없었으며**그리고** *비네트 보정*이 켜져 있었습니다 |
| **센서 응답**| `Sensor_Response_Images/` | 이 프레임은 반사율 보정이 불가능했으며**또한** *비네트 보정* 기능이 꺼져 있었습니다 |
| **화이트 밸런스 적용** | `White_Balanced_Images/` | 화이트 밸런스가 적용된 결과물이 생성되었습니다 |

{% hint style="info" %}
**비네트 보정과 센서 반응은 상호 배타적이며, 두 가지가 동시에 적용될 수 없습니다.** 각 카메라 모델별로 실행당 정확히 하나의 미보정 대체 산출물이 존재하며, *비네트 보정* 스위치가 이를 선택합니다. [프로젝트 설정](../project-settings/project-settings.md)을 참조하십시오.
{% endhint %}

### LATTICE 레벨

LATTICE는 단일 처리 단계에서 다음 레벨로 팬 아웃(fan out)을 캡처합니다. 어떤 레벨이 존재하는지는 프로젝트 설정의 제품별 내보내기 토글과 해당 카메라에 적용되는 설정에 따라 달라집니다.

| 레이어 | 저장 위치 | 적용 대상 |
| --- | --- | --- |
| **RAW (디베이어 처리됨)** | `Debayered_Images/` | RGB 및 다중 스펙트럼 |
| **RAW (미리보기)** | `Preview_Images/` | 다중 스펙트럼 (거짓색 확장) |
| **화이트 밸런스 적용** | `Preview_Images/` | RGB 마스터 카메라 — RGB 미리보기는 동일한 이름의 Survey3 레이어와 정렬되도록 이 이름으로 등록되어 있습니다 |
| **RAW (방사도)** | `Radiance_Images/` | 다중 스펙트럼 전용 |
| **RAW (반사도)** | `Reflectance_Calibrated_Images/` | 다중 스펙트럼 전용이며, 일치하는 `.daq` 하향 기록이나 QA 검수를 통과한 프레임 내 타겟이 해당 프레임을 덮고 있는 경우에만 적용 |

RGB 마스터 카메라에는 밴드별 방사계 측정이 없으므로, 해당 카메라의 경우 복사도 및 반사도는 **적용 불가**로 처리되어 생략됩니다. — 로그에 해당 내용이 기록되며, 오류가 발생해도 아무런 메시지가 표시되지 않습니다.

### 인덱스, LUT 및 샌드박스 레이어

| 레이어 패턴 | 예시 | 출처 |
| --- | --- | --- |
| **RAW (`<INDEX>` 인덱스)** | `RAW (NDVI Index)` | 프로젝트 설정에서 구성된 인덱스당 하나씩, 처리 중에 계산됨 |
| **`<INDEX>` LUT** | `NDVI LUT` | 인덱스의 색상 매핑된 버전 |
| **샌드박스 (`<Name>` `<Index\|LUT>` `<NNN>`)** | `Sandbox (NDVI LUT 003)` | [인덱스/LUT 샌드박스](index-lut-sandbox.md) 내보내기 실행당 하나씩 |

동일한 인덱스 이름이 서로 다른 설정으로 두 번 이상 구성되면, 두 번째 및 그 이후의 인덱스 이름에는 숫자가 추가되어(`RAW (NDVI2 Index)`) 레이어를 구분할 수 있게 됩니다.

## 레이어 선택기 사용법

1. 그리드에서 썸네일을 클릭하여 이미지를 전체 화면으로 엽니다.
2. 뷰어 오른쪽 상단의 **레이어 드롭다운**을 클릭합니다.
3. 레이어를 선택하면 이미지가 즉시 업데이트됩니다.

드롭다운 메뉴에는 **JPG, RAW(원본), RAW(대상), RAW(반사율)**이 해당 순서대로 맨 위에 표시되며, 그 뒤에는 제품이 등록된 순서대로 나머지 항목이 나열됩니다.

### 탐색 시 레이어 우선순위

**←**/**→** 키를 누르면 다음 이미지로 이동하며, 동일한 레이어를 유지하도록 시도합니다:

1. **이름과 정확히 일치하는 레이어 우선** — 다음 이미지에 이름이 동일한 레이어가 있으면 해당 레이어가 선택됩니다. 이 기능 덕분에 전체 세트를 차례로 살펴보는 동안에도 `RAW (NDVI Index)` 레이어에 계속 머물 수 있습니다.
2. **그 다음 유형별 일치** — 인덱스 레이어는 모든 인덱스 레이어를, LUT는 모든 LUT를, 반사율은 반사율 레이어를, 타겟은 타겟 레이어를, 원본은 원본 레이어를, 베이스는 베이스 레이어를 찾습니다.
3. **그 다음, 내보내기 레이어의 경우에만** — 레이어 목록이 아직 업데이트되지 않았더라도 파일은 디스크에 이미 존재하므로 이름이 유지됩니다. 덕분에 실행이 진행 중일 때도 결과물을 미리 검토할 수 있습니다.
4. **그 외의 경우** — 사용 가능한 첫 번째 레이어(일반적으로 기본 이미지)를 사용합니다.

프로젝트 내의 `.daq` 및 `.csv` 사이드카 파일은 화살표 키 탐색 시 건너뛰어지므로, 이미지를 순차적으로 이동할 때 광센서 기록 이미지에 도달하지 않습니다.

확대/축소 및 이동 기능은 이미지 간에도 적용되므로, 동일한 필드 위치의 전후 비교가 간편합니다.

## 레이어별 픽셀 값 이해

[커서 값 패널](opening-an-image-full-screen.md#cursor-values)은 커서가 위치한 위치의 실제 채널별 값을 해당 레이어가 저장된 단위로 표시합니다. 열의 내용은 레이어에 따라 달라집니다:

| 레이어 | 표시 단위 | 참고 사항 |
| --- | --- | --- |
| 기본 (JPG / PNG / TIFF 미리보기) | DN, 0–255 | 표시 값이며, RGB에서 감마 보정됨. 시각적 확인용 |
| RAW (원본) | DN | 센서의 원시 디지털 수치. 히스토그램 축을 통해 비트 심도를 확인할 수 있습니다: 255 (8비트), 4095 (12비트) 또는 65535 (16비트) |
| RAW (디베이어 처리됨) | DN | 선형, 표시 범위 확장 없음 |
| RAW (미리보기) / 화이트 밸런스 적용 | DN | 표시용 결과물 — 범위 확장 또는 감마 보정됨. 측정용이 아님 |
| RAW (방사도) | **W/m²/sr/nm** | Float32 물리 방사도. DN 열 없음 |
| RAW (반사율) | DN **및 %** | 해당 파일 고유의 척도로 계산된 백분율 — 아래 참조 |
| 인덱스 / LUT / 샌드박스 내보내기 | 인덱스 값 또는 RGB 구성 요소 | 단일 채널 인덱스 파일은 인덱스 값을 보고하며, 컬러 매핑된 LUT 파일은 Red/Green/Blue 구성 요소를 보고합니다 |

### 반사율: 척도는 파일별로 다릅니다

{% hint style="warning" %}
**&quot;65,535로 나누기&quot;는 Survey3에만 해당됩니다.** LATTICE 반사율은 다른 척도로 저장되며, 두 나눗수를 혼용하는 것은 반사율 값이 실제 값의 정확히 절반이 되는 가장 흔한 원인입니다.
{% endhint %}

| 출처 | 반사율 1.0에 해당하는 DN | 식별 정보 |
| --- | --- | --- |
| **LATTICE**(M3C / M3M) |**32768** | 모든 LATTICE 반사율 내보내기 파일에 찍혀 있는 XMP 태그 `Chloros:PixelScale=32768`. 2배의 헤드룸은 ρ가 1.0을 초과하더라도 잘리지 않고 표현 가능함을 의미합니다 |
| **Survey3**|**65535** | Chloros XMP 스케일 태그가 없는 경우 — Survey3 보정값은 ρ × dtype-max를 기록하며 1.0에서 클리핑됩니다 |

GIS 및 스크립팅용: 파일에서 `Chloros:PixelScale`를 읽어와 이를 나눕니다. 태그가 없는 경우, 파일은 Survey3 스케일(65535)을 사용합니다. 뷰어, 인덱스/LUT 샌드박스 및 인덱스 내보내기 기능은 모두 동일한 방식으로 스케일을 처리하므로, 커서 위치에서 읽은 숫자가 인덱스 계산에 사용된 숫자입니다.

해당 스케일 위에 추가되는 형식별 저장 방식:

* **TIFF (32비트, 백분율)**는 DN / 65535를 부동 소수점(float)으로 저장합니다
* **PNG (8비트)**및**JPG (8비트)**는 DN × 255 / 65535를 저장합니다
* **8비트 소스 캡처 파일을**8비트 TIFF 형식으로 내보낼 경우**는 재조정되지 않고 0–255 범위로 잘리며, 의도적으로 스케일 태그가 포함되지 않습니다. 패널에는 해당 파일에 대해서만 DN이 표시되며, 백분율 열은 표시되지 않습니다.

### 인덱스 값 범위

| 인덱스 계열 | 일반적인 범위 | 판독값 |
| --- | --- | --- |
| 정규화된 차분 (NDVI, GNDVI, NDRE, ENDVI…) | −1 ~ +1 | 건강한 식생은 일반적으로 0.4–0.9; 맨땅은 0 근처; 물은 음수 |
| 토양 보정 (SAVI, OSAVI, MSAVI2…) | 대략 −1 ~ +1.5 | 토양 배경이 제거된 NDVI와 유사한 수치 |
| 비율 (GRVI, GCI, MSR, CIRE…) | 상한 없음 | 분모 대역이 0에 가까워질수록 비율이 무한대로 증가 |
| EVI / LAI | 0 ~ ~1, 0 ~ ~3.5 | 구름 및 기타 포화 픽셀로 인해 두 값 모두 범위 밖으로 벗어나므로, 먼저 마스크 처리해야 함 |

각 프리셋의 정확한 공식은 [다중 스펙트럼 지수 공식](../project-settings/multispectral-index-formulas.md)을 참조하십시오.

## 일반적인 워크플로우

### 전후 비교

1. **RAW (원본)**을 선택하고 비네팅 현상과 보정되지 않은 값을 확인합니다.
2. **RAW (반사율)**으로 전환합니다.
3. 비교 — 비네팅이 제거되고 값이 보정되었습니다. 확대/축소 및 이동이 고정되므로 동일한 지면을 보고 있는 것입니다.

### 전체 세트에 걸쳐 하나의 인덱스 검토

1. 첫 번째 처리된 이미지를 열고 인덱스 레이어를 선택합니다.
2. **→** 키를 반복해서 누릅니다. 인덱스 레이어가 이미지 간을 따라 이동합니다.
3. 진행하면서 사이드바의 히스토그램을 확인하세요. 분포가 급격히 변하는 프레임은 자세히 살펴볼 가치가 있습니다.

### 보정 타겟 확인

1. 대상 프레임에서 **RAW (Target)**을 선택합니다.
2. 대상이 선명하게 보이고 감지되었는지 확인합니다.
3. 다음 대상 프레임으로 이동하면 대상 레이어가 따라옵니다.

### 반사율 값의 정확성 확인

1. **RAW (Reflectance)**를 선택합니다.
2. 커서 값 패널에서 **%** 열을 확인하세요. 해당 파일에 맞게 이미 올바르게 스케일링되어 있습니다.
3. 프레임 내 알려진 물질과 비교하여 타당성을 확인하세요. 건강한 식물은 NIR 값이 높고 적색 값이 낮습니다. 보정 타겟은 공개된 반사율 값과 유사하게 표시되어야 합니다.

## 문제 해결

### 예상했던 레이어가 드롭다운 목록에 없습니다

**가능한 원인**

* 이미지가 처리되지 않았습니다 — 베이스와 `RAW (Original)`만 존재합니다
* 프로젝트 설정에서 해당 제품의 내보내기 토글이 선택 해제되어 있음
* 해당 제품이 해당 카메라에 적용되지 않음(RGB 마스터의 경우 복사도 및 반사도; 단일 대역 M3M 모노 카메라의 경우 모든 지수)
* 반사율 보정에 사용할 데이터가 없었습니다. `.daq` 하향 복사 커버리지가 없고, QA 검증을 통과한 프레임 내 타겟도 없었기 때문에, 해당 프레임은 비네트 보정(Vignette Corrected) 또는 센서 응답(Sensor Response)으로 대체되었습니다

**해결 방법**

1. 실행 로그를 확인하십시오: Chloros에는 요청된 내보내기 제품을 생성할 수 없었던 시점과 그 이유가 명시되어 있습니다.
2. [프로젝트 설정](../project-settings/project-settings.md)에서 제품별 내보내기 토글을 확인하십시오.
3. 프로젝트 출력 트리에 해당 제품 폴더가 있는지 확인하십시오.
4. 해당 제품을 활성화한 상태에서 재처리하십시오.

### 레이어 목록이 최신 상태가 아닌 것으로 보입니다.

Chloros는 실행이 진행 중일 때 프로젝트의 제품 폴더를 재스캔하며, 디스크에 실제로 존재하는 데이터를 기반으로 누락된 레이어 등록 정보를 보정합니다. 따라서 정상적으로 내보내기가 완료된 레이어는 폴링 과정에서 자동으로 표시됩니다. 이미지를 다른 화면으로 전환했다가 다시 돌아오면 새로운 해상도로 강제 적용됩니다.

### 반사율 값이 정상 값의 절반 정도로 표시됩니다

거의 확실하게 LATTICE 파일을 65535로 나누고 있는 것입니다. `Chloros:PixelScale`(32768)를 사용하거나, 이미 해당 값이 적용된 **%** 열을 참조하십시오.

### 인덱스 레이어가 존재하지만 이미지가 비어 있습니다

인덱스에는 해당 레이어에 없는 밴드가 필요합니다. 예를 들어, 1채널 또는 2채널 파일에 적용된 세 번째 채널을 읽는 인덱스가 이에 해당합니다. 다중 밴드 레이어(반사율 또는 디베이어 처리된 레이어)로 전환하거나, 카메라 필터에 맞는 인덱스를 선택하십시오.
