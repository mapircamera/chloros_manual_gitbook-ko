# 처리 완료

Chloros의 처리가 완료되면, 결과를 검토하고 출력 품질을 확인한 후, 워크플로우에서 사용할 수 있도록 처리된 이미지를 준비해야 합니다. 이 페이지에서는 마지막 단계와 다음 조치에 대해 안내합니다.

## 처리 완료 표시

처리가 성공적으로 완료되면 다음과 같은 몇 가지 표시가 나타납니다.

* ✅ **진행률 표시줄**: 100% 완료됨
* ✅ **디버그 로그**: 카운트(이미지, 카메라 그룹, 타겟, 보정된 이미지, 기록된 파일 수)가 포함된 마지막 `[RUN-SUMMARY]` 줄이 표시됨
* ✅ **시작 버튼**: 다시 활성화됩니다(다음 처리 실행 준비 완료).
* ✅ **출력 파일**: 처리된 모든 이미지가 프로젝트의 출력 트리(아래)에 저장됩니다.

{% hint style="warning" %}
**이미지를 하나도 기록하지 못한 실행은 실패로 간주됩니다.** 이미지 산출물을 요청했으나 실행 과정에서 아무것도 기록되지 않은 경우, Chloros는 이를 실패로 보고합니다. 로그 이름에 포함된 `[RUN-SUMMARY]`는 가능한 원인(수입된 데이터 없음, 대상 미탐지, 또는 요청된 모든 산출물이 적용 불가로 건너뜀)을 암시합니다. 이에 상응하는 CLI는 0이 아닌 종료 코드를 반환합니다. 의도적으로 메타데이터만 처리하는 실행(모든 내보내기 결과물 비활성화, 인덱스 없음)은 여전히 성공으로 간주됩니다. [CLI 참조](../reference/cli-reference.md#a-run-that-writes-no-images-fails)를 참조하십시오.
{% endhint %}

## 처리된 이미지 찾기

### 출력 폴더 열기

1. **메인 메뉴** <img src="../.gitbook/assets/image (1) (1) (1) (1).png" alt="" data-size="line">
아이콘(왼쪽 상단)을 클릭합니다.
2. **"프로젝트 폴더 열기"**를 선택합니다.
3. 파일 탐색기가 프로젝트 디렉터리로 열립니다.
4. 이름으로 프로젝트를 찾습니다.

### 출력 트리

출력 파일은 **프로젝트 폴더 아래에, 카메라별로 그룹화된 후 파일 형식별로** 저장됩니다:

```
<project>/
└── LATT-M3M-L41-F550/                  # one folder per camera
    ├── tiff16/
    │   ├── Reflectance_Calibrated_Images/
    │   ├── Debayered_Images/
    │   ├── Preview_Images/
    │   └── NDVI_Index_Images/           # one folder per selected index
    └── tiff32/
        └── Radiance_Images/             # float32 radiance always lands here
```

* **카메라 폴더**: LATTICE의 경우 `LATT-<sensor>-<lens>-F<filter>` (캡처된 이미지의 EXIF 정보인 `Model`와 일치), `<model>_<filter>`는 Survey3용(예: `Survey3N_RGN`). 센서와 필터는 동일하지만 렌즈가 다른 두 대의 카메라는 별도의 폴더 구조를 갖습니다. 비네팅, 시야각 및 왜곡이 다르기 때문입니다.
* **포맷 폴더**: 내보내기 형식 설정에 따릅니다 — `tiff16`, `tiff8`, `png8`, `jpg8`, TIFF (32비트, 백분율)의 경우 `tiff32`. 라디언스(Radiance)는 항상 float32 형식이며, 항상 `tiff32` 폴더에 저장됩니다.
* **결과 폴더**:
  * `Reflectance_Calibrated_Images/` — 보정된 반사율
  * `Debayered_Images/` — 선형 디베이어링 처리(LATTICE): 다크 오프셋 제거 및 디모자이징 처리, 플랫 필드 또는 언믹스 처리 없음, 센서의 기본 방향 유지
  * `Preview_Images/` — 디스플레이 미리보기 (LATTICE)
  * `Radiance_Images/` — float32 스펙트럼 복사도, W/m²/sr/nm (LATTICE 다중 스펙트럼)
  * `Vignette_Corrected_Images/` **또는** `Sensor_Response_Images/` — 반사율 기준값이 없는 프레임에 대한 보정되지 않은 대체 데이터; 실행당 두 개 중 정확히 하나만 존재하며, 비네트 보정 설정에 따라 선택됨
  * `<INDEX>_Index_Images/` — 선택된 인덱스당 하나의 폴더 (예: `NDVI_Index_Images`)
* **`clamp_masks/`** (1.3.0 버전부터 추가, LATTICE 다중 스펙트럼 M3C 카메라 전용): 방사도 또는 반사율 제품에서 밴드 분리 과정에서 클리핑된 음수 값이 0으로 변환될 때, 제품 폴더 옆의 형식 폴더에 나타납니다. 이 폴더에는 영향을 받은 각 제품당 하나의 픽셀별 마스크가 포함됩니다(예: `tiff16/clamp_masks/Reflectance_Calibrated_Images/<name>_clampmask.tif`). 마스크는 제품 폴더 내에 절대 포함되지 않으므로, 제품 폴더를 있는 그대로 사진측량 소프트웨어에 전달할 수 있습니다. [클램프 마스크](../output-image-formats.md#clamp-masks)를 참조하십시오.

{% hint style="info" %}
**내보낸 모든 제품은 원본 파일의 이름을 유지합니다.**`capture_..._raw.tif`의 복사도 내보내기 파일은 여전히 `capture_..._raw.tif`라고 불리며, 단지 `tiff32/Radiance_Images/` 폴더에 위치할 뿐입니다.**폴더가 제품을 식별하며, 파일 이름이 아닙니다**. 따라서 `*radiance*.tif`를 검색해도 아무것도 찾지 못합니다. 대신 디렉터리를 기준으로 일치 여부를 확인하십시오.
{% endhint %}

### 파일 수는 몇 개여야 할까요?

공식을 통해 계산하지 마십시오 — 출력 파일 수는 어떤 제품이 활성화되었는지, 그리고 각 카메라에 어떤 제품이 적용되는지에 따라 달라집니다(예: RGB 카메라에는 방사도/반사도 데이터가 생성되지 않습니다). 정확한 개수는 로그에 기록되어 있습니다. 마지막 `[RUN-SUMMARY]` 줄에는 정확히 몇 개의 파일이 작성되었는지 표시되며, 힌트 줄에는 생략된 항목에 대한 설명이 나와 있습니다.

## 반사율 픽셀 값 읽기 (GIS / Pix4D / 스크립트)

반사율은 정수형 DN으로 저장되며, **ρ = 1.0에 해당하는 DN 값은 원본 카메라에 따라 달라집니다**:

| 원본 카메라 | ρ = 1.0에 해당하는 값 | 확인 방법                                        |
| --------------- | ---------- | -------------------------------------------------- |
| LATTICE (M3C/M3M) | **32768** (ρ 2.0까지 여유) | 파일에 XMP 태그 `Chloros:PixelScale=32768`가 찍혀 있음 |
| Survey3          | **65535** (ρ 1.0에서 클리핑됨)     | `Chloros:PixelScale` 태그 없음 — 이 부재가 바로 신호입니다 (Survey3제품에는 다른 `Chloros:*` 처리 태그가 포함되어 있습니다) |

**`Chloros:PixelScale` 태그를 읽고 그 값으로 나누십시오**. 일률적으로 65535를 가정해서는 안 됩니다. LATTICE 반사율을 65535로 나누면 모든 값이 아무런 경고 없이 절반으로 줄어듭니다. 1.3.0 이전 버전에서 8비트로 작성된 반사율 파일은 재조정되지 않고 잘려졌으며, 스케일 태그가 없습니다: 값을 나누는 대신 16비트 또는 32비트로 다시 내보내십시오. 자세한 내용은 [출력 이미지 형식](../output-image-formats.md)을 참조하십시오.

## 내보내기 시 포함되는 메타데이터

모든 출력 파일은 원본 캡처의 **GPS 블록**과**EXIF 하위 IFD**를 유지하므로,
내보내기 시 `FocalLength`, `FNumber`, `ExposureTime`, `ISO`, `DateTimeOriginal` 및
`CameraSerialNumber`를 지리 참조 정보와 함께 포함합니다.

{% hint style="warning" %}
**오르토모자이크의 축척이 터무니없이 나오면, 먼저 `FocalLength`를 확인하십시오.**
Pix4D는 초점 거리와 고도를 바탕으로 지상 샘플 간격을 계산합니다. 이 태그가 없으면
극도로 잘못된 축척으로 계산됩니다. 49회 촬영으로 측정된 한 비행 사례에서, 411m × 160m
오렌지 과수원이 47.8 km × 13 km로 재구성되어, 대부분이
빈 공간으로 채워진 455메가픽셀의 정사영상이 생성되기도 했습니다. 타일링 속도가 느려지고 예상치 못하게 파일 크기가 커지는 현상은 이 문제의 증상일 뿐, 별개의
문제가 아닙니다.

```bash
exiftool -FocalLength -GPSLatitude "YourProject/.../some_export.tif"
```
{% endhint %}

*모든* 태그가 복사되는 것은 아닙니다. IFD0의 구조적 태그는 의도적으로 제외되었으며(이들을 복사하면
LATTICE 출력이 손상됨), `ExifImageWidth` / `ExifImageHeight`는
원본 캡처를 설명하기 때문에 제외됩니다. 크기가 조정된 내보내기 파일의 경우, 그렇지 않으면
자신의 래스터와 모순되는 치수를 주장하게 될 것입니다.

Chloros는 또한 각 제품에 어떤 처리가 이루어졌는지를 설명하는 자체 `Chloros:*` XMP 태그를 작성합니다
(예: `Chloros:ProcessingLevel`, `Chloros:CalibrationApplied`,
`Chloros:VignetteCorrected`). 1.3.0 버전부터, Survey3 산출물은 모든 처리
모드에서 이 태그를 포함하며, 인덱스 제품은 원본 원시 데이터의 태그를 반복하는 대신 인덱스 자체(`Chloros:ProcessingLevel=index`,
공식, 그리고 반사도 또는 복사도 중 어느 것을 기반으로 계산되었는지)를 기술하며, 260자보다 깊은 폴더에 있는 제품들도 메타데이터를
유지합니다. [출력 이미지 형식](../output-image-formats.md#index-products)을 참조하십시오.

## 디버그 로그 검토

### 경고 또는 오류 확인

1. **디버그 로그** <img src="../.gitbook/assets/icon_log.JPG" alt="" data-size="line">
탭을 엽니다.
2. 메시지를 스크롤하여 확인합니다.
3. 노란색 경고나 빨간색 오류를 찾습니다.
4. `[RUN-SUMMARY]` 줄과 관련 힌트를 읽습니다.
5. 도움이 필요하면 MAPIR지원팀에 문의하십시오.

### 로그 저장하기

처리 내역을 기록하거나 MAPIR지원팀에 보내려면:

1. **"복사"**또는**"다운로드"** 버튼을 클릭합니다.
2. 프로젝트 폴더에 텍스트 파일로 저장합니다.
3. 프로젝트 문서에 포함시킵니다.
4. 문제가 발생하면 MAPIR지원팀에 보내세요

문제를 MAPIR에 직접 보고하려면 디버그 로그 탭 상단의 버그 아이콘(**버그 신고**)을 사용하세요 — [로그 탭에서 버그 신고하기](monitoring-the-processing.md#reporting-a-bug-from-the-log-tab)를 참조하십시오.

## 일반적인 출력 문제 및 해결 방법

### 문제: 출력 파일이 누락됨

**가능한 원인:**

* 해당 제품에 해당 카메라가 적용되지 않음(예: RGB 카메라용 방사도/반사도 — 로그에 해당 내용이 표시됨)
* 필수 참조 정보가 누락되었습니다(예: 타겟 및 `.daq` 하향 복사량이 없는 반사도).
* 프로젝트 설정에서 해당 제품의 내보내기 확인란이 비활성화되어 있습니다.
* 내보내기 도중 디스크 공간이 부족했습니다.

**해결 방법:**

1. 디버그 로그에서 `[RUN-SUMMARY]` 힌트와 `[EXPORT-CHECK]` 항목을 확인하십시오. 여기에는 카메라별 처리 생략 사유가 설명되어 있습니다.
2. [프로젝트 설정](adjusting-project-settings.md)에서 내보내기 항목의 체크박스가 선택되어 있는지 확인하십시오.
3. 디스크 공간이 충분한지 확인하십시오.
4. 원인을 수정한 후 다시 처리하십시오.

### 문제: 가장자리가 어둡거나 밝은 경우 (비네팅이 여전히 보임)

**가능한 원인:**

* 비네팅 보정 기능이 비활성화됨
* 카메라/렌즈가 Chloros 프로필 데이터베이스에 없음
* 보정 범위를 초과하는 극심한 비네팅

**해결 방법:**

1. 프로젝트 설정에서 비네팅 보정이 활성화되었는지 확인하십시오.
2. 카메라 모델이 올바르게 감지되었는지 확인하십시오.
3. 비네팅 현상이 지속되면 MAPIR지원팀에 문의하십시오.

### 문제: 색상 또는 값이 부정확함

**가능한 원인:**

* 보정 타겟이 감지되지 않음
* 잘못된 보정 타겟 모델이 선택됨
* 반사율 보정이 비활성화됨
* 타겟 이미지 품질이 낮음

**해결 방법:**

1. 반사율 보정이 활성화되었는지 확인
2. 디버그 로그에서 “타겟 발견” 메시지 확인
3. 타겟 이미지 품질 검토
4. 올바른 타겟을 표시하여 재처리

### 문제: NDVI 값이 잘못된 것으로 보임

**예상 NDVI 범위:**

* **물, 암석, 토양**: -0.1 ~ 0.2
* **희소하거나 건강하지 않은 식생**: 0.2 ~ 0.4
* **보통 수준의 식생**: 0.4 ~ 0.6
* **건강하고 울창한 식생**: 0.6 ~ 0.9**값이 이 범위 밖인 경우:**

1. 반사율 보정이 적용되었는지 확인
2. 광 센서 로그가 포함되었는지 확인
3. 보정 타겟이 감지되었는지 확인
4. 올바른 카메라 모델이 감지되었는지 확인
5. 타겟 이미지 촬영 시점과 조건을 검토하십시오
6. 반사율 파일을 사용하여 지수를 직접 계산하는 경우, 파일의 `Chloros:PixelScale` 값으로 나눈 것인지 확인하십시오(위 참조)

## 처리된 이미지 사용

### 사진측량 / 정사모자이크 생성용

**권장 워크플로우:**

1.**보정된 반사율 이미지를** 사진측량 소프트웨어로 가져오기:
   * Pix4Dmapper
   * Agisoft Metashape
   * DroneDeploy
   * WebODM
2. **EXIF 메타데이터 유지**: 지오태깅을 위해 GPS 데이터가 보존되도록 합니다.
3. **보정된 워크플로우**: 과학적 정확성을 위해 반사도 이미지를 사용합니다. — LATTICE 반사도 이미지에는 Pix4D가 읽을 수 있는 XMP 보정 태그가 포함되어 있습니다.
4. **지수 모자이크 처리**: 개별 지수 이미지를 사용하여 NDVI정사모자이크를 생성합니다.
5. **지오레퍼런싱된 GeoTIFF 내보내기**: GIS 애플리케이션에서 사용하기 위함

### GIS 분석용

**권장 워크플로우:**

1.**QGIS, ArcGIS 또는 유사 소프트웨어에 불러오기**

2.**16비트 TIFF** 반사율 이미지를 사용하여 다중 대역 분석 수행 (파일의 `Chloros:PixelScale` 값으로 나눕니다)
3. **지수 이미지** (NDVI, NDRE)를 바로 사용 가능한 식생 레이어로 활용
4. **래스터 계산기**: 사용자 정의 분석을 위해 밴드 결합
5. **내보내기**: 분류 지도 생성, 변화 감지, 식생 건강 지도 생성

### 직접 분석/보고용

**권장 워크플로우:**

1.**LUT 색상이 적용된 지수 이미지**를 사용하여 시각적 보고서 작성
2. **통계 추출**: 필드/플롯별 평균 NDVI

3. **시계열 분석**: 여러 세션에 걸친 지수 비교
4. **보고서 생성**: 지도, 통계 및 시각화 자료 포함***

## 후처리 문제 해결

### 다른 설정으로 재처리

결과가 만족스럽지 않은 경우:

1. 원본 이미지를 보관하십시오(절대 삭제하지 마십시오).
2. Chloros에서 동일한 프로젝트를 엽니다. 3. 프로젝트 설정 패널에서 설정을 조정합니다.
4. 다시 처리합니다. — 결과물은 동일한 제품 폴더에 저장되므로, 이전 실행에서 생성된 동일한 이름의 파일은 덮어쓰게 됩니다.

### 이미지 일부만 처리하기

특정 이미지만 다시 처리하려면:

1. 새 프로젝트를 생성합니다.
2. 다시 처리해야 하는 이미지만 가져옵니다.
3. 동일한 설정 템플릿을 사용합니다.
4. 더 작은 데이터셋을 처리합니다.
