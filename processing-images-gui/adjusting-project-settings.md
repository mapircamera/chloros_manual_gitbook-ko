# 프로젝트 설정 조정

이미지를 처리하기 전에 워크플로우 요구 사항에 맞게 프로젝트 설정을 구성하는 것이 중요합니다. ‘프로젝트 설정’<img src="../.gitbook/assets/icon_project-settings.JPG" alt="" data-size="line"> 패널을 통해 보정, 처리 옵션, 다중 스펙트럼 지수 및 내보내기 형식을 포괄적으로 제어할 수 있습니다.

## 프로젝트 설정 열기

1. Chloros에서 프로젝트를 엽니다.
2. 왼쪽 사이드바에서 **프로젝트 설정** <img src="../.gitbook/assets/icon_project-settings.JPG" alt="" data-size="line"> 아이콘을 클릭합니다.
3. 프로젝트 설정 패널에 모든 구성 옵션이 표시됩니다.

<figure><img src="../.gitbook/assets/image (28).png" alt=""><figcaption><p>프로젝트 설정 패널 — 표시, 대상 감지 및 처리</p></figcaption></figure>{% hint style="info" %}
**설정은 프로젝트와 함께 자동으로 저장됩니다**. 프로젝트를 다시 열면 모든 설정이 복원됩니다.
{% endhint %}

## 일반적인 워크플로우를 위한 빠른 설정

### 기본 설정 (대부분의 사용자에게 권장)

기본 설정은 일반적인 Survey3 및 LATTICE 워크플로우에 적합합니다:

* ✅ **비네팅 보정**: 사용
* ✅ **반사율 보정 / 화이트 밸런스**: 사용 (MAPIR 타겟 및/또는 DAQ 광센서 데이터 사용)
* ✅ **디베이어 방식**: 표준 (빠름, 중간 품질)
* ✅ **내보내기 형식**: TIFF (16비트)
* ✅ **모든 내보내기 결과물**: 활성화됨 (LATTICE는 디베이어링, 미리보기, 방사도 및 반사도 데이터로 자동 분할하여 캡처합니다)

이미지를 가져온 후 이 기본 설정으로 처리를 시작하기만 하면 됩니다.

## 프로젝트 설정 개요

프로젝트 설정 패널은 아래 섹션으로 구성되어 있습니다. 프로젝트에 관련 파일이 포함되어 있으면 **DAQ 광 센서**및**어레이 정렬**이라는 두 가지 추가 섹션이 자동으로 표시됩니다. 전체 문서는 [프로젝트 설정](../project-settings/project-settings.md)을 참조하십시오.

### 표시

* **이미지 썸네일 해상도**: 이미지 그리드 썸네일의 해상도입니다. 옵션:**기본값 (512 px)**,**1024 px**,**2048 px**,**전체 해상도**. 표시 전용 — 처리 과정에는 전혀 영향을 미치지 않습니다. 값이 높을수록 확대 시 더 선명하게 보이지만 로딩 속도는 느려집니다.

### 타겟 감지

Chloros가 이미지에서 보정 타겟을 식별하는 방식을 제어합니다.

**주요 설정:*** **최소 보정 샘플 영역 (px)**: 타겟 감지를 위한 크기 임계값 (기본값:**25**, 범위 0–10000)
* **최소 타겟 클러스터링 (0-100)**: 타겟 영역을 그룹화하기 위한 유사도 임계값 (기본값:**60**)**조정 시점:**

* 오탐지가 발생하면 샘플 영역을 늘리세요
* 타겟이 감지되지 않으면 줄이세요
* 타겟이 여러 개의 감지 결과로 분할되는 경우 클러스터링 값을 조정하세요

{% hint style="info" %}
**반사율 보정/화이트 밸런스**가 꺼져 있으면 이 설정들은 비활성화됩니다. 이 기능이 꺼져 있으면 표적 감지 기능이 전혀 실행되지 않습니다.
{% endhint %}

### 처리

주요 이미지 처리 및 보정 옵션입니다.

**주요 설정:*** **비네팅 보정**: 이미지 가장자리의 렌즈 어두워짐 현상을 보정합니다 ✅ 권장
* **반사율 보정 / 화이트 밸런스**: 감지된 타겟(Survey3) 및/또는 DAQ 광센서 데이터(LATTICE)를 사용하여 이미지를 보정합니다. ✅ 권장
* **디베이어(Debayer) 방식**: RAW를 3채널 다중 스펙트럼으로 변환하는 알고리즘
* **최소 재보정 간격**: 보정 타겟 사용 간 최소 시간(초 단위) (기본값:**0** = 모두 사용, 범위 0–3600)**보정되지 않은 대체 산출물:**프레임에 대한 반사율 보정이 불가능한 경우(표적 없음 또는 보정 비활성화), 다음 두 가지 대체 산출물 중 하나로 내보내집니다.**실행당 이 쌍 중 정확히 하나만 생성되며**, 비네트 보정 스위치에 따라 선택됩니다:

* **센서 응답 내보내기**: `Sensor_Response_Images`를 작성합니다 — 비네트 보정이**꺼짐**일 때 사용됩니다
* **비네트 보정된 데이터 내보내기**: `Vignette_Corrected_Images`를 작성합니다 — 비네트 보정이**켜져** 있을 때 사용됩니다

현재 선택되지 않은 체크박스는 회색으로 표시됩니다. 활성화된 체크박스의 선택을 해제하면 해당 파일이 전혀 작성되지 않습니다.

**LATTICE 내보내기 결과물** (모든 프로젝트에 표시되며, LATTICE 캡처에 적용됨):

* **디베이어 처리된 이미지 내보내기**: 선형 디베이어 처리된 이미지(`Debayered_Images`). RGB 및 다중 스펙트럼 모듈에 적용됩니다.
* **미리보기 내보내기**: 화면 미리보기 이미지(`Preview_Images`). RGB = 화이트 밸런스(사용 가능한 경우 DAQ 광원, 그렇지 않으면 그레이 월드) + 감마; 다중 스펙트럼 = 가색 확장.
* **방사도 내보내기**: float32 스펙트럼 방사도(`Radiance_Images`, W/m²/sr/nm). 다중 스펙트럼 모듈에만 해당 — RGB 마스터에는 적용되지 않습니다.
* ****반사도 내보내기**: uint16 반사도 (`Reflectance_Calibrated_Images`, DN 32768 = ρ 1.0). `.daq` 하향 복사 측정값 또는 프레임 내 타겟이 프레임을 덮고 있는 경우. 다중 스펙트럼 모듈에만 해당됩니다.

네 가지 설정 모두 **기본적으로 활성화되어 있습니다**— 가져온 LATTICE 원시 프레임 하나는 단일 처리 단계에서 활성화된 모든 해당 제품으로 분산 처리됩니다.**반사율 내보내기** 확인란은 반사율 보정이 비활성화되어 있을 때 회색으로 표시됩니다. 상위 스위치 설정으로 인해 적용이 불가능한 설정은 항상 회색으로 표시되며, 변경해야 할 스위치 이름이 툴팁으로 표시됩니다.**고급 설정:*** **광 센서 시간대 오프셋**: 광 센서 시간 일치를 위한 UTC 기준 시간(시간 단위, 기본값: 0, 범위 −12~+12)
* **PPK 보정 적용**: `.daq` 파일의 GPS/노출 핀 데이터를 사용합니다(기본값: 끄기)
* **노출 핀 1/2**: 듀얼 카메라 설정에서 카메라를 노출 핀에 할당합니다

{% hint style="info" %}
**LATTICE 입력 레벨은 자동으로 설정됩니다.** LATTICE 캡처 파일은 XMP 메타데이터에 처리 레벨 정보를 포함하며, 처리는 항상 원본 프레임 단계에서 파이프라인으로 들어갑니다. 따라서 GUI에서 별도로 구성할 항목이 없습니다. (CLI 플래그인 `--input-level`는 메타데이터가 손실된 캡처에 대한 고급 사용자용 재정의 옵션으로 존재합니다. [CLI 참조](../reference/cli-reference.md)를 참조하십시오.)
{% endhint %}

### 디베이어 방식

현재 Chloros에서는 2가지 디베이어 방식을 제공합니다:

#### 표준 (빠름, 중간 품질)

표준 디베이어는 처리 속도가 빠르지만 디베이어링으로 인한 색상 노이즈가 나타나, 정확도가 떨어지고 노이즈가 많은 이미지를 생성합니다.

#### 텍스처 인식 (느림, 최고 품질) \[Chloros+ 전용]

텍스처 인식은 고품질의 에지 인식 디베이어링과 AI/ML 노이즈 제거 모델을 결합하여 디베이어링 노이즈를 거의 모두 제거합니다. 이 모델을 실행하려면 GPU 메모리(VRAM)가 필요합니다. **7GB 이상의 VRAM**이 있을 경우 여러 이미지를 동시에 처리할 수 있으며, 7GB 미만일 경우 한 번에 하나의 이미지만 처리합니다(속도가 눈에 띄게 느려집니다). [동적 컴퓨팅 적응(Dynamic Compute Adaptation)](../processing-architecture/dynamic-compute-adaptation.md)을 참조하십시오.

{% hint style="info" %}
**LATTICE로 촬영한 이미지는 항상 표준 디모자이크를 사용합니다.** LATTICE용으로 훈련된 텍스처 인식 모델이 없으므로, LATTICE 영상에는 이 옵션이 제공되지 않습니다. 단, 동일한 프로젝트 내의 Survey3 이미지는 여전히 이 기능을 사용할 수 있습니다.
{% endhint %}

### 지수 (다중 스펙트럼 지수)

계산 및 내보낼 식생 지수를 구성합니다. GUI 드롭다운 메뉴에는 **27개의 사전 정의된 지수 공식**이 제공됩니다.**지수 추가 방법:**

1.**&quot;지수 추가&quot;** 버튼을 클릭합니다.
2. 드롭다운 메뉴에서 지수를 선택합니다(NDVI, NDRE, GNDVI 등).
3. 시각화 설정(LUT 색상, 값 범위)을 구성합니다.
4. 필요에 따라 여러 지수를 추가합니다.

**자주 사용되는 지수:*** **NDVI**: 일반적인 식생 건강도 (가장 일반적)
* **NDRE**: RedEdge를 활용한 조기 스트레스 감지
* **GNDVI**: 엽록소 농도에 민감
* **OSAVI**: 가시광선 영역의 토양과 잘 어울림
* **EVI**: 높은 잎 면적 지수(LAI) 지역**사용자 정의 공식:**

* 모든 이미지 채널에 대한 밴드 연산을 통해 사용자 정의 다중 스펙트럼 지수 공식을 생성
* 재사용을 위해 사용자 정의 공식 저장
* 사용자 정의 공식은 Chloros+ 기능이며, 이용 가능 여부는 요금제 등급에 따라 다름

사용 가능한 모든 지수 및 공식(GUI에서만 사용 가능한 이름과 CLI/SDK에서도 작동하는 이름 포함)에 대해서는 [다중 스펙트럼 지수 공식](../project-settings/multispectral-index-formulas.md)을 참조하십시오.

### 내보내기

출력 파일 형식을 제어합니다.

**사용 가능한 형식**(설정:**보정된 이미지 형식**, 기본값**TIFF (16비트)**):

* **TIFF (16비트)**: GIS 및 과학적 분석에 권장
* **TIFF (32비트, 백분율)**: 부동 소수점 값
* **PNG (8비트)**: 시각화를 위한 무손실 압축
* **JPG (8비트)**: 파일 크기가 가장 작으며, 손실 압축

출력 파일은 프로젝트 폴더 아래에 카메라 및 형식별로 그룹화되어 저장됩니다(예: `<project>/<camera>/<format>/<Product>_Images/`). 이 설정과 관계없이 Radiance는 **항상** float32 형식으로 `tiff32` 폴더에 저장됩니다. 내보낸 파일은 원본 파일명을 유지하며, 폴더 이름으로 결과물을 식별합니다. 전체 출력 구조에 대해서는 [처리 완료](finishing-the-processing.md)를 참조하십시오.

{% hint style="warning" %}
**반사율 값 읽기**: ρ = 1.0을 나타내는 DN은 소스 카메라에 따라 다릅니다. LATTICE는 32768(XMP `Chloros:PixelScale`로 기록됨)을 사용하고, Survey3는 65535를 사용합니다. 상수를 가정하기보다는 태그를 직접 확인하십시오. [출력 이미지 형식](../output-image-formats.md)을 참조하십시오.
{% endhint %}

### DAQ 광 센서

이 섹션에는 프로젝트에 포함된 모든 DAQ 하향 복사 파일(`.daq` / `.csv`)이 파일당 한 행씩 나열되어 있으며, 센서 모델, 파일 이름 및 해당 파일에 적용되는 디퓨저 **캡** 보정값이 표시됩니다.

* **캡 오버라이드 (모든 파일)**: 프로젝트 전체에 적용되는 단일 드롭다운 메뉴입니다.**자동**(기본값)은 각 파일에 기록된 캡을 사용합니다. 기록된 내용이 없는 경우 햇빛 조건으로 간주되는데, 이는 모든 MAPIR DAQ에 햇빛 보정기가 기본으로 포함되어 있기 때문입니다. 캡을 선택하면 모든 파일에 대해 설정값이 재정의됩니다. 원시 기록 데이터는 해당 캡으로 보정되며, 이미 캡이 적용된 기록 데이터는 기준이 재설정됩니다(기록된 보정값이 취소되고, 선택한 캡이 적용됨).
* 기록된 상한값이 운영자가 확인한 것이 아니라 허브의 기본값인 경우, 그리고 선택한 상한값에 해당 장치 모델에 대한 프로필이 없는 경우(해당 파일에 대해서는 재설정이 거부됨) 행에 경고가 표시됩니다.

&#x27;광 센서&#x27; 탭에서 생성된 DAQ 기록은 열려 있는 프로젝트에 자동으로 추가되며, 가져온 `.daq` / `.csv` 파일은 추가되는 즉시 여기에 표시됩니다.

이 섹션은 프로젝트 내의 이미지 중 적어도 하나에 LATTICE 어레이가 캡처 시 스탬프하는 모듈 간 정렬 변환(`Chloros:Alignment*` XMP)이 포함된 경우에만 표시됩니다. 이 섹션은 태그가 적용된 이미지 수와 기준이 되는 카메라를 표시하며, 다음과 같은 제어 기능을 제공합니다:

* **어레이 정렬 적용** (기본값: 켜짐): 처리된 모든 결과물(디베이어링 / 미리보기 / 방사도 / 반사도 / 인덱스)을 어레이의 공통 기준 기하 구조로 변환합니다. 끔 = 센서의 원본 기하 구조로 내보냅니다.
* **공통 중첩 영역으로 자르기** (기본값: 켜짐): 정렬된 내보내기 파일을 모든 모듈이 공유하는 영역으로 잘라내어, 모든 밴드가 동일한 촬영 범위를 갖도록 합니다. 끄면 전체 센서 캔버스가 유지됩니다(소스 외부는 검은색으로 채워짐).
* **리샘플링**:**이선형(부드러움, 기본값)**,**최인접(정확한 값 보존)**— 픽셀 간 혼합 없음, 엄격한 방사계 분석용 — 또는**3차(가장 선명함)**.***

## 설정 저장 및 불러오기

### 프로젝트 템플릿 저장

일관된 워크플로우를 위해 재사용 가능한 템플릿을 생성합니다:

1. 프로젝트 설정 패널에서 원하는 모든 설정을 구성합니다.
2. 하단의 **&quot;프로젝트 템플릿 저장&quot;** 섹션으로 스크롤합니다.
3. 설명이 포함된 템플릿 이름을 입력합니다(예: &quot;Survey3N\_RGN\_Agriculture&quot;)
4. 저장 아이콘을 클릭합니다

**장점:**

* 여러 프로젝트에 동일한 설정을 적용할 수 있습니다
* 팀원들과 구성을 공유할 수 있습니다
* 반복되는 설문조사에서 일관성을 유지할 수 있습니다

### 새 프로젝트에 템플릿 불러오기

새 프로젝트를 생성할 때:

1. 메인 메뉴에서 **&quot;새 프로젝트&quot;**를 선택합니다
2. 선택 사항인 템플릿 선택기에서 프로젝트 템플릿을 선택합니다
3. 템플릿의 모든 설정이 자동으로 적용됩니다

### 작업 디렉터리

**&quot;작업 디렉터리&quot;** 설정은 새 프로젝트가 기본적으로 생성될 위치를 지정합니다:

* **기본 위치**: `C:\Users\[Username]\Chloros Projects`
* **위치 변경**: 편집 아이콘을 클릭하고 새 폴더를 선택합니다
* **CLI와 공유**: `chloros-cli`는 동일한 기본 프로젝트 폴더 설정을 사용합니다
* **변경해야 할 경우**:
  * 팀 협업을 위한 네트워크 드라이브
  * 저장 공간이 더 많은 별도의 드라이브
  * 연도/고객별로 체계적으로 정리된 폴더 구조

## PPK(사후 처리 운동학) 설정

정밀한 지리적 위치 파악을 위해 GPS가 탑재된 MAPIR DAQ 레코더를 사용하는 경우:

### 필수 조건

* GPS(GNSS) 모듈이 장착된 MAPIR DAQ
* 노출 핀 항목이 포함된 .daq 로그 파일
* 캡처 세션 동안 DAQ의 노출 핀에 연결된 카메라

### 구성 단계

1. .daq 로그 파일을 프로젝트 폴더에 배치합니다.
2. 프로젝트 설정에서 **&quot;PPK 보정 적용&quot;** 확인란을 선택합니다.
3. 필요한 경우 **&quot;광 센서 시간대 오프셋&quot;**을 설정합니다(기본값: UTC 기준 0).
4. 카메라를 노출 핀에 할당합니다:
   * **단일 카메라**: 핀 1에 자동으로 할당됩니다
   * **듀얼 카메라**: 각 카메라를 올바른 핀에 수동으로 할당합니다**노출 핀 할당:*** **노출 핀 1**: 드롭다운 메뉴에서 카메라 모델을 선택합니다
* **노출 핀 2**: 두 번째 카메라를 선택하거나 &quot;사용 안 함&quot;을 선택합니다
* 동일한 카메라를 두 핀에 모두 할당할 수 없습니다

{% hint style="warning" %}
**중요**: 노출 핀은 각 카메라에 올바르게 할당되어야 합니다. 잘못 할당할 경우 잘못된 위치 정보가 생성됩니다.
{% endhint %}

## 고급 시나리오

### 다중 카메라 프로젝트

하나의 프로젝트에서 여러 대의 MAPIR 카메라로 촬영된 이미지를 처리할 경우:

1. Chloros는 각 카메라 모델(Survey3 및 LATTICE 등)을 자동으로 감지합니다.
2. 각 카메라에는 적절한 처리 프로필이 적용되며, 각 카메라마다 고유한 출력 폴더 구조가 생성됩니다.
3. PPK: 각 Survey3 카메라를 올바른 노출 핀에 수동으로 할당합니다.
4. 모든 카메라는 동일한 내보내기 형식과 인덱스를 사용합니다.

**예시**: Survey3W, RGN + Survey3N, OCN 듀얼 카메라 리그, 또는 RGB 마스터와 협대역 모듈을 혼합한 LATTICE 어레이

### 타임랩스 또는 다일자 조사

시간이 지남에 따라 동일한 지역을 반복적으로 조사하는 경우:

1. 표준 설정이 포함된 템플릿을 생성하십시오
2. 매 세션마다 일관된 보정 타겟 설정을 사용하십시오
3. 각 날짜의 데이터를 별도의 프로젝트로 처리하십시오
4. 비교 가능한 결과를 얻기 위해 동일한 설정을 사용하십시오
5. 시계열 분석을 위해 동일한 형식으로 내보내십시오

### 대규모 데이터 세트

이미지가 많은(500장 이상) 프로젝트의 경우:

* 날짜나 지역별로 더 작은 프로젝트로 나누는 것을 고려하세요
* 더 빠른 결과를 얻으려면 Chloros+ 병렬 처리를 사용하세요
* 일괄 처리를 자동화하려면 CLI 또는 API 사용을 고려하세요
* 대상 탐지 시간을 단축하기 위해 최소 재보정 간격을 조정하십시오

## 설정 확인

* [ ] PPK 설정이 구성되었는지(노출 이벤트가 포함된 .daq 파일을 사용하는 경우)
