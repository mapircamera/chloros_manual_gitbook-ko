# 처리 현황 모니터링

처리가 시작되면 Chloros는 진행 상황을 모니터링하고, 문제를 확인하며, 데이터셋의 처리 현황을 파악할 수 있는 여러 가지 방법을 제공합니다. 이 페이지에서는 처리 과정을 추적하고 Chloros가 제공하는 정보를 해석하는 방법을 설명합니다.

## 진행률 표시줄 개요

상단 헤더의 진행률 표시줄은 실시간 처리 상태와 완료율을 보여줍니다. 진행 상황은 서버 전송 이벤트(SSE)를 통해 백엔드에서 실시간으로 전송되므로, 진행률 표시줄은 파이프라인의 실제 실행 상태를 반영합니다.

### 무료 모드 진행률 표시줄

Chloros+ 라이선스가 없는 사용자의 경우:

**2단계 진행 상황 표시:**

1.**타겟 감지** - 이미지에서 보정 타겟 찾기
2. **처리** - 보정 적용 및 내보내기**진행률 표시줄에 표시되는 내용:**

* 전체 완료율 (0-100%)
* 현재 단계 이름
* 간단한 수평 막대 시각화

### Chloros+ 진행률 표시줄

Chloros+ 라이선스를 보유한 사용자의 경우:

**4단계 진행률 표시:**

1.**탐지** - 보정 대상 찾기
2. **분석** - 이미지 검토 및 파이프라인 준비
3. **보정** - 비네팅 및 반사율 보정 적용
4. **내보내기** - 처리된 파일 저장**상호작용 기능:*** 진행률 표시줄 위에 **마우스를 올리면** 4단계 패널이 확장되어 표시됩니다.
* 진행률 표시줄을 **클릭하면** 확장된 패널이 고정됩니다.
* **다시 클릭하면** 고정이 해제되며, 마우스를 떼면 자동으로 숨겨집니다.
* 각 단계별로 개별 진행률(0-100%)이 표시됩니다.

{% hint style="info" %}
**CLI 패리티**: `chloros-cli process` 실행 중, 동일한 4개의 스레드가 ‘탐지 중’, ‘분석 중’, Processing, Exporting 상태인 것으로 보고되며, `chloros-cli export-status`는 다른 터미널에서 Thread-4의 실시간 내보내기 진행 상황을 보여줍니다. [CLI 참조](../reference/cli-reference.md)를 참조하십시오.
{% endhint %}

## 각 처리 단계 이해하기

{% hint style="info" %}
**파이프라인 아키텍처**: 이 4가지 GUI 단계는 [4-스레드 처리 파이프라인](../processing-architecture/processing-pipeline.md)에 해당합니다. GPU 가속이 지원되는 시스템에서 스레드 3(보정 중)은 특정 하드웨어에 맞게 처리를 최적화하는 [동적 컴퓨트 적응](../processing-architecture/dynamic-compute-adaptation.md)의 이점을 받아 사용자의 특정 하드웨어에 맞게 처리를 최적화합니다.
{% endhint %}

### 1단계: 탐지 (타겟 탐지)

**진행 과정:**

* Chloros는 [대상] 확인란을 선택한 이미지를 스캔합니다(아무것도 선택하지 않은 경우 모든 이미지를 스캔합니다).
* 컴퓨터 비전 알고리즘이 보정 패널을 식별합니다.
* 각 패널에서 반사율 값을 추출합니다.
* 정확한 보정 일정을 위해 대상 타임스탬프를 기록합니다.

**소요 시간:**

* 타겟이 표시된 경우: 10~60초
* 타겟이 표시되지 않은 경우: 5~30분 이상 (모든 이미지 스캔)

**진행률 표시기:**

* 탐지 중: 0% → 100%
* 스캔된 이미지 수 (실제로 스캔된 이미지만 집계)
* 발견된 타겟 수

**주의 사항:**

* 타겟이 올바르게 표시되어 있다면 빠르게 완료되어야 함
* 시간이 너무 오래 걸린다면 타겟이 표시되지 않았을 수 있음
* 디버그 로그에서 “Target found” 메시지 확인

### 2단계: 분석

**진행 내용:**

* 이미지 EXIF 메타데이터(타임스탬프, 노출 설정) 읽기
* 타겟 타임스탬프 및 사용 가능한 DAQ 하향 데이터에 기반하여 보정 전략 결정
* 이미지 처리 대기열 구성
* 병렬 처리 워커 준비 (Chloros+ 전용)

**소요 시간:** 5~30초**진행 상태 표시기:**

* 분석 중: 0% → 100%
* 빠른 단계로, 대개 신속하게 완료됨

**주의 사항:**

* 중단 없이 꾸준히 진행되어야 함
* 누락된 메타데이터에 대한 경고가 디버그 로그에 표시됨

### 3단계: 보정

**진행 내용:*** **베이어 제거**: RAW 베이어 패턴을 3채널로 변환 (LATTICE 모노 모듈의 경우 건너뛰며, 관련 참고 사항 있음)
* **비네팅 보정**: 렌즈 가장자리의 어두워진 부분 제거
* **반사율 보정**: 목표값 및/또는 DAQ 하향 복사량에 따라 정규화
* **지수 계산**: 다중 스펙트럼 지수 계산
* 전체 파이프라인을 통해 각 이미지 처리

**소요 시간:** 전체 처리 시간의 대부분(60~80%)**진행 상황 표시기:**

* 보정 중: 0% → 100%
* 현재 처리 중인 이미지
* 처리 완료된 이미지 / 총 이미지 수

**처리 방식:*** **자유 모드**: 한 번에 하나의 이미지를 순차적으로 처리합니다.
* **Chloros+ 모드**: 하드웨어에 적응하는 워커 풀을 실행합니다. GPU 시스템에서는 VRAM 용량에 따라 1~4개의 워커가 동시에 실행되며, CPU 전용 시스템에서는 물리적 코어당 1개(1개 제외)의 워커가 실행됩니다. [동적 연산 적응](../processing-architecture/dynamic-compute-adaptation.md)을 참조하십시오.
* **GPU 가속**: 이 단계의 처리 속도를 대폭 향상시킵니다.**주의 사항:**

* 이미지 수에 따른 안정적인 진행 상황
* 디버그 로그에서 이미지별 완료 메시지 확인
* 이미지 품질 또는 보정 문제에 대한 경고

### 4단계: 내보내기

**진행 과정:**

* 처리가 완료된 이미지를 선택한 형식으로 디스크에 기록합니다.
* **LATTICE**: 각 프레임은 활성화된 모든 제품(데베이어링 / 미리보기 / 방사도 / 반사도)으로 분산됩니다.
* LUT 색상이 적용된 다중 스펙트럼 인덱스 이미지 내보내기
* 출력 트리 `<project>/<camera>/<format>/<Product>_Images/` 생성 — 내보낸 파일은 원본 파일 이름을 유지하며, 폴더명은 산출물을 나타냅니다

**소요 시간:** 전체 처리 시간의 10~20%**진행 상태 표시기:**

* 내보내기: 0% → 100%
* 파일 쓰기 중
* 내보내기 형식 및 저장 위치

**주의 사항:**

* 디스크 공간 경고
* 파일 쓰기 오류
* 구성된 모든 출력의 완료 여부

## 디버그 로그 탭

디버그 로그는 처리 진행 상황 및 발생한 문제에 대한 상세 정보를 제공합니다. 백엔드 시작 메시지도 로그 콘솔에 기록되므로, 로그를 늦게 열더라도 전체 진행 상황을 파악할 수 있습니다.

### 디버그 로그에 액세스하기

1. 왼쪽 사이드바에서 **디버그 로그**<img src="../.gitbook/assets/icon_log.JPG" alt="" data-size="line">

아이콘을 클릭합니다.
2. 실시간 처리 메시지가 표시된 로그 패널이 열립니다.
3. 최신 메시지를 볼 수 있도록 자동으로 스크롤됩니다.

<!-- SCREENSHOT-NEEDED: Debug Log tab open at the end of a completed run, showing real backend log lines including the [RUN-SUMMARY] lines (images / camera groups / targets / calibrated / files written) -->

### 로그 메시지 이해하기

Chloros 로그 줄의 앞부분에는 서브시스템 이름을 나타내는 대괄호로 묶인 태그가 붙습니다. 예를 들어 `[PROCESSING]`, `[RUN-SUMMARY]`, `[LATTICE-EXPORT]`, `[EXPORT-CHECK]`, `[IMPORT-LEVEL]`와 같습니다. 가장 중요하게 알아야 할 것은 **실행 요약**이며, 모든 실행(중단된 실행 포함)의 끝에 출력됩니다:

```
[RUN-SUMMARY] 49 image(s) in 2 camera group(s); 4 target(s) detected; 45 image(s) calibrated; 180 file(s) written.
```

추가적인 설명이 필요한 경우(예: 아무런 결과도 산출하지 못한 실행, 또는 요청된 산출물이 적용 불가능하여 건너뛴 카메라의 경우입니다. `[EXPORT-CHECK]` 행은 카메라별 건너뛰기 사유를 설명합니다(예: RGB 카메라가 왜 복사도 산출물을 얻지 못했는지 등).

일반적인 메시지 심각도(아래 예시는 설명을 위한 것이며, 정확한 문구는 아닙니다):

#### 정보 메시지(흰색/회색)

일반적인 처리 업데이트: 처리 시작, 대상 감지(패널 수 포함), 이미지별 보정 진행 상황, 파일 내보내기, 처리 완료.

#### 경고 메시지 (노란색)

처리를 중단시키지 않는 비중대한 문제 — 예: 프레임 내 GPS 데이터 누락, 대상 이미지 간 타임스탬프 간격이 큰 경우, 또는 보정 패널의 대비가 낮은 경우.

**조치:** 처리 후 경고를 검토하되, 처리를 중단하지 마십시오

#### 오류 메시지 (Red)

처리가 실패할 수 있는 심각한 문제 — 예: 디스크 용량 부족, 이미지 파일 손상, 반사율 보정이 요청되었으나 대상물이 탐지되지 않은 경우 등.

**조치:** 처리를 중지하고, 오류를 해결한 후 다시 시작하십시오.

### 일반적인 로그 상황

| 상황                             | 의미                                       | 필요한 조치                                         |
| ------------------------------------- | --------------------------------------------- | ----------------------------------------------------- |
| [파일 이름]에서 타겟 감지됨        | 보정 타겟을 성공적으로 찾음                 | 없음 - 정상                                         |
| 이미지별 진행률 표시줄              | 현재 진행 상황 업데이트                       | 없음 - 정상                                         |
| 타겟을 찾을 수 없음                      | 보정 타겟이 감지되지 않음               | 타겟 이미지를 표시하거나 반사율 보정을 비활성화하십시오 |
| 디스크 공간 부족               | 출력용 저장 공간이 부족합니다                 | 디스크 공간을 확보하십시오                                    |
| 손상된 파일 건너뛰기               | 이미지 파일이 손상되었습니다                         | SD 카드에서 파일을 다시 복사하십시오                             |
| `[IMPORT-LEVEL] Skipping ... no raw source` | 원시 프레임이 없는 캡처는 처리할 수 없습니다 | 원시 프레임과 함께 다시 캡처하거나 CLI, `--input-level`를 사용하십시오 |
| `[RUN-SUMMARY] ... 0 file(s) written` | 실행 결과 이미지 산출물이 생성되지 않음 — 실패로 보고되며 힌트가 제공됨 | 힌트 내용을 확인하고, 무엇이 생략되었는지 및 그 이유를 확인하십시오 |

### 로그 데이터 복사

문제 해결 또는 지원을 위해 로그를 복사하려면:

1. 디버그 로그 패널을 엽니다.
2. **&quot;로그 복사&quot;** 버튼을 클릭합니다(또는 마우스 오른쪽 버튼 클릭 → 모두 선택).
3. 텍스트 파일이나 이메일에 붙여넣습니다.
4. 필요한 경우 MAPIR 지원팀에 전송합니다.

## 시스템 리소스 모니터링

### CPU 사용량

**프리 모드:**

* 1개의 CPU 코어가 ~100% 사용 중
* 다른 코어는 유휴 상태이거나 사용 가능
* 시스템은 정상적으로 반응함

**Chloros+ 병렬 모드:**

* 여러 코어가 높은 사용률을 보임 — 정확한 개수는 [동적 컴퓨팅 적응(Dynamic Compute Adaptation)](../processing-architecture/dynamic-compute-adaptation.md)에서 선택한 전략에 따라 다름
* 시스템 반응 속도가 다소 느려질 수 있음

**모니터링 방법:**

* Windows 작업 관리자 (Ctrl+Shift+Esc)
* 성능 탭 → CPU 섹션
* &quot;Chloros&quot; 또는 &quot;chloros-backend&quot; 프로세스 확인

### 메모리(RAM) 사용량

**일반적인 사용량:**

* 소규모 프로젝트 (&lt; 100개 이미지): 2~4 GB
* 중규모 프로젝트 (100~500개 이미지): 4~8 GB
* 대규모 프로젝트 (500개 이상 이미지): 8~16 GB
* Chloros+ 병렬 모드는 더 많은 RAM을 사용합니다

**메모리가 부족한 경우:**

* 더 작은 배치 단위로 처리하세요
* 다른 애플리케이션을 종료하세요
* 대규모 데이터 세트를 정기적으로 처리하는 경우 RAM을 업그레이드하세요

### GPU 사용량 (CUDA를 사용하는 Chloros+)

GPU 가속이 활성화된 경우:

* NVIDIA GPU 사용률이 높게 나타납니다(60~90%).
* VRAM 사용량이 증가합니다(4GB 이상의 VRAM 필요; 텍스처 인식 디베이어링(Texture Aware debayering)을 동시에 수행할 경우 7GB 이상 필요).
* 보정 단계의 속도가 현저히 빨라집니다

**모니터링 방법:**

* NVIDIA 시스템 트레이 아이콘
* 작업 관리자 → 성능 → GPU
* GPU-Z 또는 유사한 모니터링 도구

### 디스크 I/O

**예상되는 현상:**

* 분석 단계에서 높은 디스크 읽기량 발생
* 내보내기 단계에서 디스크 쓰기량이 높음
* SSD가 HDD보다 훨씬 빠름

**성능 팁:**

* 가능하면 프로젝트 폴더에 SSD를 사용하세요
* 대용량 데이터 세트의 경우 네트워크 드라이브 사용을 피하세요
* 디스크 용량이 거의 꽉 차지 않았는지 확인하세요(쓰기 속도에 영향을 미침)

## 처리 중 문제 감지

### 경고 신호

**진행 상황이 멈춤(5분 이상 변화 없음):**

* 디버그 로그에서 오류 확인
* 사용 가능한 디스크 공간 확인
* 작업 관리자에서 Chloros가 실행 중인지 확인

**오류 메시지가 자주 표시됨:**

* 처리를 중지하고 오류를 검토하십시오
* 일반적인 원인: 디스크 공간 부족, 파일 손상, 메모리 문제
* 아래의 ‘문제 해결’ 섹션을 참조하십시오

**시스템이 응답하지 않음:**

* Chloros+ 병렬 모드가 너무 많은 리소스를 사용 중입니다
* 동시 작업 수를 줄이거나 하드웨어를 업그레이드하는 것을 고려하십시오
* 프리 모드는 리소스 소모가 적습니다

### 처리를 중지해야 하는 경우

다음과 같은 현상이 나타나면 처리를 중지하십시오:

* ❌ “디스크 용량 부족” 또는 “파일 쓰기 불가” 오류
* ❌ 반복되는 이미지 파일 손상 오류
* ❌ 시스템이 완전히 멈춤(응답 없음)
* ❌ 잘못된 설정이 적용되었음을 확인한 경우
* ❌ 잘못된 이미지를 가져온 경우

**중지 방법:**

1.**중지 버튼**(시작 버튼 대신 표시됨)을 클릭하십시오 — 한 번만 클릭하면 됩니다
2. 진행 중인 이미지 처리가 완료되는 동안 진행 바에 &quot;중지 중...&quot;이 표시된 후, 실행이 중지된 상태로 종료됩니다
3. 이미 내보낸 결과물은 디스크에 그대로 남아 있으며, 로그에는 완료된 작업에 대한 정확한 정보(`[RUN-SUMMARY]`)가 기록됩니다
4. 문제를 해결하고 다시 시작하면 — 실행이 처음부터 시작됩니다

***

## 처리 중 문제 해결

### 처리 속도가 매우 느림

**가능한 원인:**

* 타겟 이미지가 표시되지 않음 (모든 이미지 스캔 중)
* SSD 대신 HDD 저장 장치 사용
* 시스템 리소스 부족
* 설정된 인덱스가 많음
* 네트워크 드라이브 액세스

**해결 방법:**

1. 방금 시작하여 ‘탐지 중’ 단계인 경우: 중지 후 대상 이미지를 표시하고 다시 시작
2. 향후 조치: SSD 사용, 인덱스 수 줄이기, 하드웨어 업그레이드
3. 대용량 데이터셋을 일괄 처리할 때는 CLI 사용 고려

### &quot;디스크 공간&quot; 경고

**해결 방법:**

1. 즉시 디스크 공간을 확보하십시오.
2. 프로젝트가 저장된 드라이브를 용량이 더 큰 드라이브로 이동하십시오.
3. 내보낼 인덱스 수를 줄이십시오.
4. 필요하지 않은 LATTICE 내보내기 항목을 비활성화하십시오(프로젝트 설정 → 처리).
5. TIFF 대신 JPG 형식 사용 (파일 크기 감소)

### 빈번한 “파일 손상” 메시지

**해결 방법:**

1. SD 카드에서 이미지를 다시 복사하여 무결성을 확인하십시오
2. SD 카드에 오류가 있는지 검사하십시오
3. 프로젝트에서 손상된 파일을 제거하십시오
4. 나머지 이미지 처리를 계속하십시오

### 시스템 과열 / 성능 저하

**해결 방법:**

1. 통풍이 잘 되도록 하십시오
2. 컴퓨터 통풍구에서 먼지를 제거하십시오
3. 처리 부하를 줄이십시오(Chloros+ 대신 Free 모드를 사용하십시오)
4. 하루 중 기온이 낮은 시간에 처리하십시오

***

## 처리 완료 알림

처리가 완료되면:

* 진행률 표시줄이 100%에 도달합니다
* 디버그 로그에 최종 카운트가 포함된 `[RUN-SUMMARY]` 줄이 표시됨
* 시작 버튼이 다시 활성화됨
* 모든 출력 파일이 프로젝트의 카메라별 출력 폴더(`<project>/<camera>/<format>/<Product>_Images/`)에 있음
