# 처리 현황 모니터링

처리가 시작되면 Chloros는 진행 상황을 모니터링하고, 문제를 확인하며, 데이터셋의 처리 현황을 파악할 수 있는 여러 가지 방법을 제공합니다. 이 페이지에서는 처리 과정을 추적하고 Chloros가 제공하는 정보를 해석하는 방법을 설명합니다.

## 진행률 표시줄 개요

상단 헤더의 진행률 표시줄은 실시간 처리 상태와 완료율을 보여줍니다. 진행 상황은 서버 전송 이벤트(SSE)를 통해 백엔드에서 실시간으로 전송되므로, 이 표시줄은 파이프라인이 실제로 수행 중인 작업을 반영합니다.

### 무료 모드 진행률 표시줄

Chloros+ 라이선스가 없는 사용자의 경우:

**2단계 진행 상황 표시:**

1.**타겟 감지** - 이미지에서 보정 타겟 찾기
2. **처리** - 보정 적용 및 내보내기**진행률 표시줄에 표시되는 내용:**

* 전체 완료율 (0-100%)
* 현재 단계 이름
* 간단한 수평 막대 시각화

### Chloros+ 진행률 표시줄

Chloros+ 라이선스를 보유한 사용자의 경우:

**4단계 진행률 표시:**

1.**탐지** - 보정 대상 찾기
2. **분석** - 이미지 검토 및 파이프라인 준비
3. **보정** - 비네팅 및 반사율 보정 적용
4. **내보내기** - 처리된 파일 저장

**상호작용 기능:**

* 진행률 표시줄 위에 **마우스를 올리면** 4단계 패널이 확장되어 표시됩니다.
* 진행률 표시줄을 **클릭하면** 확장된 패널이 고정됩니다.
* **다시 클릭**하면 고정 해제되며, 마우스를 떼면 자동으로 숨겨짐
* 각 단계별로 개별 진행 상황(0-100%)이 표시됨

{% hint style="info" %}
**CLI와 동일성**: `chloros-cli process` 실행 중에는 동일한 4개의 스레드가 ‘탐지 중’, ‘분석 중’, ‘처리 중’, ‘내보내기 중’으로 보고되며, `chloros-cli export-status`는 다른 터미널에서 스레드 4의 실시간 내보내기 진행 상황을 보여줍니다. [CLI 참조](../reference/cli-reference.md)를 참조하십시오.
{% endhint %}

## 각 처리 단계 이해

{% hint style="info" %}
**파이프라인 아키텍처**: 이 4가지 GUI 단계는 [4스레드 처리 파이프라인](../processing-architecture/processing-pipeline.md)에 해당합니다. GPU 가속이 지원되는 시스템에서는, 스레드 3(보정)은 사용자의 특정 하드웨어에 맞게 처리를 최적화하는 [동적 컴퓨트 적응(Dynamic Compute Adaptation)](../processing-architecture/dynamic-compute-adaptation.md)의 이점을 활용합니다.
{% endhint %}

### 1단계: 탐지(대상 탐지)

**진행 과정:**

* Chloros는 ‘타겟’ 체크박스를 선택한 이미지를 스캔합니다(체크된 항목이 없을 경우 모든 이미지를 스캔).
* 컴퓨터 비전 알고리즘이 보정 패널을 식별합니다.
* 각 패널에서 반사율 값을 추출합니다.
* 정확한 보정 일정을 위해 타겟 타임스탬프를 기록합니다.

**소요 시간:**

* 타겟이 표시된 경우: 10~60초
* 타겟이 표시되지 않은 경우: 5~30분 이상 (모든 이미지 스캔)

**진행 상황 표시기:**

* 탐지 중: 0% → 100%
* 스캔된 이미지 수 (실제로 스캔 중인 이미지만 집계)
* 발견된 타겟 수

**주의 사항:**

* 타겟이 올바르게 표시되어 있다면 빠르게 완료되어야 함
* 시간이 너무 오래 걸린다면 타겟이 표시되지 않았을 수 있음
* 디버그 로그에서 "Target found" 메시지 확인

### 2단계: 분석

**진행 내용:**

* 이미지 EXIF 메타데이터(타임스탬프, 노출 설정) 읽기
* 타겟 타임스탬프 및 사용 가능한 DAQ 하향 데이터에 기반하여 보정 전략 결정
* 이미지 처리 대기열 구성
* 병렬 처리 워커 준비 (Chloros+ 전용)

**소요 시간:** 5~30초**진행 상태 표시기:**

* 분석 중: 0% → 100%
* 빠른 단계로, 대개 신속하게 완료됩니다

**주의 사항:**

* 중단 없이 꾸준히 진행되어야 함
* 누락된 메타데이터에 대한 경고가 디버그 로그에 표시됨

### 3단계: 보정

**진행 내용:**

* **데베이어링**: RAW 베이어 패턴을 3채널로 변환 (LATTICE 모노 모듈의 경우, 별도 안내와 함께 건너뜁니다)
* **비네트 보정**: 렌즈 가장자리의 어두워진 부분을 제거합니다
* **반사율 보정**: 목표값 및/또는 DAQ 다운웰링을 사용하여 정규화합니다
* **지수 계산**: 다중 스펙트럼 지수를 계산합니다
* 전체 파이프라인을 통해 각 이미지를 처리합니다

**소요 시간:** 전체 처리 시간의 대부분(60~80%)**진행 상황 표시기:**

* 보정 중: 0% → 100%
* 현재 이미지 처리 중
* 처리 완료된 이미지 / 총 이미지 수

**처리 방식:**

* **자유 모드**: 한 번에 하나의 이미지를 순차적으로 처리합니다.
* **Chloros+ 모드**: 하드웨어에 적응하는 워커 풀을 실행합니다. GPU 시스템에서는 VRAM 용량에 따라 1~4개의 워커가 동시에 실행되며, CPU 전용 시스템에서는 물리적 코어당(1개 제외) 하나의 워커가 실행됩니다. [동적 연산 적응](../processing-architecture/dynamic-compute-adaptation.md)
* **GPU 가속**: 이 단계를 상당히 빠르게 진행시킵니다**주의 사항:**

* 이미지 수에 따른 안정적인 진행 상황
* 디버그 로그에서 이미지별 완료 메시지 확인
* 이미지 품질 또는 보정 문제에 대한 경고

### 4단계: 내보내기

**진행 과정:**

* 처리가 완료된 이미지를 선택한 형식으로 디스크에 기록합니다.
* **LATTICE**: 각 프레임은 활성화된 모든 산출물(데베이어링 / 미리보기 / 방사도 / 반사도)로 분산됩니다.
* LUT 색상이 적용된 다중 스펙트럼 인덱스 이미지 내보내기
* 출력 트리 `<project>/<camera>/<format>/<Product>_Images/` 생성 — 내보낸 파일은 원본 파일 이름을 유지하며, 폴더명은 산출물을 나타냅니다

**소요 시간:** 전체 처리 시간의 10~20%**진행 상황 표시기:**

* 내보내기: 0% → 100%
* 파일 쓰기 중
* 내보내기 형식 및 저장 위치

**주의 사항:**

* 디스크 공간 경고
* 파일 쓰기 오류
* 구성된 모든 출력의 완료 여부

## 디버그 로그 탭

디버그 로그는 처리 진행 상황 및 발생한 문제에 대한 상세 정보를 제공합니다. 백엔드 시작 메시지도 로그 콘솔에 재현되므로, 로그를 늦게 열더라도 전체 진행 상황을 파악할 수 있습니다.

### 디버그 로그에 액세스하기

1. 왼쪽 사이드바에서 **디버그 로그**<img src="../.gitbook/assets/icon_log.JPG" alt="" data-size="line">

아이콘을 클릭합니다.
2. 실시간 처리 메시지가 표시된 로그 패널이 열립니다.
3. 최신 메시지를 표시하기 위해 자동으로 스크롤됩니다.

### 로그 메시지 이해하기

Chloros의 로그 줄 앞에는 서브시스템 이름을 나타내는 대괄호로 묶인 태그가 붙어 있습니다. 예를 들어 `[PROCESSING]`, `[RUN-SUMMARY]`, `[LATTICE-EXPORT]`, `[EXPORT-CHECK]`, `[IMPORT-LEVEL]`. 가장 중요하게 알아야 할 것은 모든 실행(중단된 실행 포함)의 끝에 출력되는 **실행 요약**입니다:

```
[RUN-SUMMARY] 49 image(s) in 2 camera group(s); 4 target(s) detected; 45 image(s) calibrated; 180 file(s) written.
```

설명이 필요한 경우(예: 아무런 결과도 산출하지 못한 실행, 또는 요청된 산출물이 적용 불가능하여 건너뛴 카메라의 경우 등입니다. `[EXPORT-CHECK]` 줄은 카메라별 건너뛰기 사유를 설명합니다(예: RGB 카메라에서 방사도 산출물이 생성되지 않은 이유).

일반적인 메시지 심각도(아래 예시는 설명을 위한 것이며, 정확한 문구는 아닙니다):

#### 정보 메시지(흰색/회색)

정상적인 처리 업데이트: 처리 시작, 대상 감지(패널 수 포함), 이미지별 보정 진행 상황, 파일 내보내기, 처리 완료.

#### 경고 메시지 (노란색)

처리를 중단시키지 않는 비중요 문제 — 예: 프레임 내 GPS 데이터 누락, 대상 이미지 간 타임스탬프 간격이 큰 경우, 또는 보정 패널의 대비가 낮은 경우.

**조치:** 처리 후 경고를 검토하되, 처리를 중단하지 마십시오.

#### 오류 메시지 (빨간색, Red)

처리가 실패할 수 있는 중대한 문제 — 예: 디스크 용량 부족, 이미지 파일 손상, 반사율 보정이 요청되었으나 대상물이 감지되지 않은 경우 등.

**조치:** 처리를 중지하고, 오류를 해결한 후 다시 시작하십시오.

### 일반적인 로그 상황

| 상황                             | 의미                                       | 필요한 조치                                         |
| ------------------------------------- | --------------------------------------------- | ----------------------------------------------------- |
| \[파일명\]에서 대상 감지됨        | 보정 대상 성공적으로 발견됨         | 없음 - 정상                                         |
| 이미지별 진행률 표시줄              | 현재 진행률 업데이트                       | 없음 - 정상                                         |
| 타겟 미검출                      | 보정 타겟이 감지되지 않음               | 타겟 이미지를 표시하거나 반사율 보정을 비활성화하십시오 |
| 디스크 공간 부족               | 출력용 저장 공간이 부족함                 | 디스크 공간을 확보하십시오                                    |
| 손상된 파일 건너뛰기               | 이미지 파일이 손상되었습니다                         | SD 카드에서 파일을 다시 복사하십시오                             |
| `[IMPORT-LEVEL] Skipping ... no raw source` | 원본 프레임이 없는 캡처는 처리할 수 없습니다 | 원본 프레임과 함께 다시 캡처하거나, CLI를 사용하십시오 `--input-level`  |
| `[RUN-SUMMARY] ... 0 file(s) written` | 실행 결과 이미지 산출물이 생성되지 않았습니다 — 힌트와 함께 실패로 보고됨 | 힌트 줄을 읽고, 무엇이 왜 건너뛴 것인지 확인하십시오 |
| `[PROCESS] refused: The project folder is too deep for this computer…` | Windows의 긴 경로 기능이 비활성화되어 있고, 프로젝트 폴더 경로가 260자 제한을 초과할 정도로 깊습니다. 아무것도 처리되지 않았습니다 | 더 짧은 프로젝트 폴더를 사용하십시오 (메시지에 허용되는 최대 길이가 표시됨)를 사용하거나, Windows 긴 경로 기능을 켜고 Chloros를 다시 시작하십시오 — [처리 시작](starting-the-processing.md#the-project-folder-is-too-deep-for-this-computer) 참조 |
| `[unmix-clamp-mask] …` | LATTICE 제품의 클램프 마스크를 기록할 수 없습니다. 제품 자체에는 문제가 없으며, 다음과 같은 메시지가 표시됩니다. `Chloros:UnmixClampMask=unavailable` | 디스크 공간과 폴더 권한을 확인한 후, 마스크가 필요한 경우 다시 처리하십시오 |

### 로그 데이터 복사

문제 해결 또는 지원을 위해 로그를 복사하려면:

1. 디버그 로그 패널을 엽니다.
2. **복사**버튼을 클릭하여(로그를 클립보드에 복사) 또는**다운로드**를 클릭하여 텍스트 파일로 저장합니다.
3. 텍스트 파일이나 이메일에 붙여넣습니다.
4. 필요한 경우 MAPIR지원팀에 전송

### 로그 탭에서 버그 신고하기

1.3.0 버전 신규 기능: 디버그 로그 탭 상단의 버그 아이콘(**버그 신고**)을 클릭하면 MAPIR로 직접 보고서가 전송됩니다.

1. 디버그 로그 탭 상단의 버그 아이콘을 클릭합니다.
2. 문제 설명: 수행 중이던 작업, 기대했던 결과, 실제로 발생한 현상 (필수)
3. 선택 사항으로 **이미지 몇 장 추가(최대 10장)**를 선택하고 열려 있는 프로젝트에서 이미지를 고르거나,**찾아보기...**를 사용하여 다른 이미지 파일을 선택하세요
4. **보내기**를 클릭하세요

이 보고서에는 설명, 첨부한 이미지, Chloros 로그 및 시스템 세부 정보(Chloros 버전, OS, GPU, 프로젝트 설정)가 포함됩니다. 보고서를 보내려면 Chloros (사용자 탭)에 로그인되어 있어야 합니다. 전송 중에는 창을 닫아도 됩니다. 전송이 완료되면 `Bug report sent. Reference: BR-…`와 같은 참조 번호가 로그에 기록됩니다. MAPIR에 문의할 때 이 번호를 인용해 주십시오. 보고서를 업로드할 수 없는 경우 (예: 인터넷 연결 불가), Chloros는 보고서를 컴퓨터에 저장하고 경로를 표시하므로, 해당 파일을 support@mapir.camera로 이메일로 전송할 수 있습니다.

## 시스템 리소스 모니터링

### CPU 사용량

**일반 모드:**

* 1개의 CPU 코어가 약 100% 사용 중
* 다른 코어는 유휴 상태이거나 사용 가능
* 시스템은 정상적으로 반응함

**Chloros+ 병렬 모드:**

* 여러 코어가 높은 사용률을 보임 — 코어 수는 [동적 컴퓨팅 적응](../processing-architecture/dynamic-compute-adaptation.md)에서 선택한 전략에 따라 다름
* 시스템 반응 속도가 다소 느려질 수 있음

**모니터링 방법:**

* Windows 작업 관리자 (Ctrl+Shift+Esc)
* 성능 탭 → CPU 섹션
* "Chloros" 또는 "chloros-backend" 프로세스 확인

### 메모리(RAM) 사용량

**일반적인 사용량:**

* 소규모 프로젝트(이미지 100장 미만): 2~4 GB
* 중규모 프로젝트(이미지 100~500장): 4~8 GB
* 대규모 프로젝트(이미지 500장 이상): 8~16 GB
* Chloros+ 병렬 모드는 더 많은 RAM을 사용합니다

**메모리가 부족할 경우:**

* 더 작은 배치 단위로 처리하세요
* 다른 애플리케이션을 종료하세요
* 대규모 데이터셋을 정기적으로 처리하는 경우 RAM을 업그레이드하세요

### GPU 사용량 (CUDA를 사용하는 Chloros+)

GPU 가속이 활성화된 경우:

* NVIDIA GPU 사용률이 높게 나타납니다 (60~90%)
* VRAM 사용량이 증가합니다(4GB 이상의 VRAM 필요; 텍스처 인식 디베이어링(Texture Aware debayering)을 동시에 수행할 경우 7GB 이상 필요)
* 보정 단계가 훨씬 빨라집니다

**모니터링 방법:**

* NVIDIA 시스템 트레이 아이콘
* 작업 관리자 → 성능 → GPU
* GPU-Z 또는 유사한 모니터링 도구

### 디스크 I/O

**예상되는 현상:**

* 분석 단계에서 높은 디스크 읽기량
* 내보내기 단계에서 높은 디스크 쓰기량
* SSD가 HDD보다 훨씬 빠름

**성능 팁:**

* 가능하면 프로젝트 폴더에 SSD를 사용하세요
* 대용량 데이터 세트의 경우 네트워크 드라이브 사용을 피하세요
* 디스크 용량이 거의 꽉 차지 않았는지 확인하세요(쓰기 속도에 영향을 미침)

***

## 처리 중 문제 감지

### 경고 신호

**진행 상황이 멈춤(5분 이상 변화 없음):**

* 디버그 로그에서 오류 확인
* 사용 가능한 디스크 공간 확인
* 작업 관리자를 통해 Chloros가 실행 중인지 확인

**오류 메시지가 빈번하게 표시되는 경우:**

* 처리를 중지하고 오류를 검토
* 일반적인 원인: 디스크 공간 부족, 파일 손상, 메모리 문제
* 아래의 ‘문제 해결’ 섹션 참조

**시스템이 응답하지 않는 경우:**

* Chloros+ 병렬 모드가 너무 많은 리소스를 사용하고 있음
* 동시 작업 수를 줄이거나 하드웨어를 업그레이드하는 것을 고려하십시오
* 프리 모드는 리소스 소모가 적습니다

### 처리를 중지해야 할 때

다음과 같은 현상이 나타나면 처리를 중지하십시오:

* ❌ “디스크 용량 부족” 또는 “파일 쓰기 실패” 오류
* ❌ 이미지 파일 손상 오류가 반복적으로 발생
* ❌ 시스템이 완전히 멈춤(응답 없음)
* ❌ 잘못된 설정이 적용된 것을 확인
* ❌ 잘못된 이미지가 가져옴

**중단 방법:**

1.**중단 버튼**(시작 버튼 대신 표시됨)을 클릭하세요 — 한 번만 클릭하면 됩니다
2. 진행 중인 이미지 처리가 완료될 때까지 진행 바에 "중단 중..."이 표시된 후, 실행이 중단된 상태로 종료됩니다
3. 이미 내보낸 결과물은 디스크에 그대로 남아 있으며, 로그에는 완료된 작업에 대한 정확한 `[RUN-SUMMARY]` 오류 코드가 출력됩니다
4. 문제를 해결하고 다시 시작하면 — 실행이 처음부터 다시 시작됩니다

***

## 처리 중 문제 해결

### 처리 속도가 매우 느림

**가능한 원인:**

* 표시되지 않은 대상 이미지(모든 이미지 스캔 중)
* SSD 대신 HDD 저장 장치 사용
* 시스템 리소스 부족
* 구성된 인덱스가 너무 많음
* 네트워크 드라이브 액세스

**해결 방법:**

1. 방금 시작하여 ‘탐지(Detecting)’ 단계인 경우: 중지 후 대상 이미지를 지정하고 다시 시작
2. 향후 조치: SSD 사용, 인덱스 수 줄이기, 하드웨어 업그레이드
3. 대용량 데이터셋 일괄 처리를 위해 CLI 사용 고려

### “디스크 공간” 경고

**해결 방법:**

1. 즉시 디스크 공간 확보
2. 프로젝트가 저장된 드라이브를 용량이 더 큰 드라이브로 이동
3. 내보낼 인덱스 수 줄이기
4. 필요 없는 LATTICE 내보내기 항목 비활성화 (프로젝트 설정 → 처리)
5. TIFF 대신 JPG 형식 사용 (파일 크기 감소)

### 빈번한 “파일 손상” 메시지

**해결 방법:**

1. SD 카드에서 이미지를 다시 복사하여 무결성을 확인하십시오
2. SD 카드에 오류가 있는지 검사하십시오
3. 프로젝트에서 손상된 파일을 제거하십시오
4. 나머지 이미지 처리를 계속하십시오

### 시스템 과열 / 성능 제한

**해결 방법:**

1. 통풍이 잘 되도록 하세요
2. 컴퓨터 통풍구의 먼지를 제거하세요
3. 처리 부하를 줄이세요(Chloros+ 대신 Free 모드 사용)
4. 하루 중 기온이 낮은 시간대에 처리하세요

***

## 처리 완료 알림

처리가 완료되면:

* 진행률 표시줄이 100%에 도달합니다
* 디버그 로그에 최종 카운트가 포함된 `[RUN-SUMMARY]` 줄이 표시됨
* 시작 버튼이 다시 활성화됨
* 모든 출력 파일이 프로젝트의 카메라별 출력 폴더(`<project>/<camera>/<format>/<Product>_Images/`)에 저장됨
