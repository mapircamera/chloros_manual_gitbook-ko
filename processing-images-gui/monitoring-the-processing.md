# 처리 현황 모니터링

처리가 시작되면 Chloros는 진행 상황을 모니터링하고, 문제를 확인하며, 데이터셋의 상태를 파악할 수 있는 여러 가지 방법을 제공합니다. 이 페이지에서는 처리 과정을 추적하고 Chloros가 제공하는 정보를 해석하는 방법을 설명합니다.

## 진행률 표시줄 개요

상단 헤더의 진행률 표시줄은 실시간 처리 상태와 완료율을 보여줍니다.

### 무료 모드 진행률 표시줄

Chloros+ 라이선스가 없는 사용자의 경우:

**2단계 진행률 표시:**

1.**타겟 감지** - 이미지에서 보정 타겟 찾기
2. **처리** - 보정 적용 및 내보내기**진행률 표시줄에 표시되는 내용:**

* 전체 완료율 (0-100%)
* 현재 단계 이름
* 간단한 수평 막대 시각화

### Chloros+ 진행률 표시줄

Chloros+ 라이선스를 보유한 사용자의 경우:

**4단계 진행 상황 표시:**

1.**탐지** - 보정 타겟 찾기
2. **분석** - 이미지 검토 및 파이프라인 준비
3. **보정** - 비네팅 및 반사율 보정 적용
4. **내보내기** - 처리된 파일 저장**상호작용 기능:*** **진행률 표시줄 위에 마우스를 올리면** 4단계 패널이 확장되어 표시됩니다
* **진행률 표시줄을 클릭하면** 확장된 패널을 고정할 수 있습니다
* **다시 클릭하면** 고정이 해제되며 마우스를 떼면 자동으로 숨겨집니다
* 각 단계별로 개별 진행률(0-100%)이 표시됩니다

## 각 처리 단계 이해하기

{% hint style="info" %}
**파이프라인 아키텍처**: 이 4개의 GUI 단계는 [4스레드 처리 파이프라인](../processing-architecture/processing-pipeline.md)에 해당합니다. GPU 가속이 지원되는 시스템에서는 스레드 3(보정)이 특정 하드웨어에 맞게 처리를 최적화하는 [동적 컴퓨트 적응](../processing-architecture/dynamic-compute-adaptation.md)의 이점을 활용합니다.
{% endhint %}

### 1단계: 감지 (타겟 감지)

**진행 과정:**

* Chloros는 &#x27;타겟&#x27; 체크박스가 선택된 이미지를 스캔합니다.
* 컴퓨터 비전 알고리즘이 4개의 보정 패널을 식별합니다.
* 각 패널에서 반사율 값을 추출합니다.
* 정확한 보정 스케줄링을 위해 타겟 타임스탬프를 기록합니다.

**소요 시간:**

* 타겟이 표시된 경우: 10~60초
* 타겟이 표시되지 않은 경우: 5~30분 이상 (모든 이미지 스캔)

**진행 상태 표시기:**

* 탐지 중: 0% → 100%
* 스캔된 이미지 수
* 발견된 타겟 수

**주의 사항:**

* 타겟이 올바르게 표시된 경우 빠르게 완료되어야 함
* 시간이 너무 오래 걸리는 경우, 타겟이 표시되지 않았을 수 있음
* 디버그 로그에서 &quot;Target found&quot; 메시지 확인

### 2단계: 분석

**진행 내용:**

* 이미지 EXIF 메타데이터(타임스탬프, 노출 설정) 읽기
* 대상 타임스탬프를 기반으로 보정 전략 결정
* 이미지 처리 대기열 구성
* 병렬 처리 워커 준비 (Chloros+ 전용)

**소요 시간:** 5~30초**진행 상태 표시기:**

* 분석 중: 0% → 100%
* 빠른 단계로, 대개 신속하게 완료됩니다

**확인 사항:**

* 중단 없이 꾸준히 진행되어야 합니다
* 메타데이터 누락에 대한 경고가 디버그 로그에 표시됩니다

### 3단계: 보정

**진행 과정:*** **데베이링(Debayering)**: RAW 베이어 패턴을 3채널로 변환
* **비네팅 보정**: 렌즈 가장자리의 어두워짐 현상 제거
* **반사율 보정**: 목표값을 기준으로 정규화
* **지수 계산**: 다중 스펙트럼 지수 계산
* 전체 파이프라인을 통해 각 이미지 처리

**소요 시간:** 전체 처리 시간의 대부분 (60~80%)**진행률 표시기:**

* 보정 중: 0% → 100%
* 현재 이미지 처리 중
* 처리 완료된 이미지 / 총 이미지 수

**처리 방식:*** **자유 모드**: 한 번에 하나의 이미지를 순차적으로 처리
* **Chloros+ 모드**: 최대 16개의 이미지를 동시에 처리
* **GPU 가속**: 이 단계의 속도를 크게 향상시킵니다**확인 사항:**

* 이미지 수에 따른 안정적인 진행 상황
* 디버그 로그에서 이미지별 완료 메시지 확인
* 이미지 품질 또는 보정 문제에 대한 경고

### 4단계: 내보내기

**진행 내용:**

* 보정된 이미지를 선택한 형식으로 디스크에 기록
* LUT 색상이 적용된 다중 스펙트럼 인덱스 이미지 내보내기
* 카메라 모델 하위 폴더 생성
* 적절한 확장자를 추가하여 원본 파일명 유지

**소요 시간:** 전체 처리 시간의 10~20%**진행 상태 표시기:**

* 내보내기: 0% → 100%
* 파일 기록 중
* 내보내기 형식 및 저장 위치

**확인 사항:**

* 디스크 공간 경고
* 파일 기록 오류
* 구성된 모든 출력 작업 완료

## 디버그 로그 탭

디버그 로그는 처리 진행 상황 및 발생한 문제에 대한 상세 정보를 제공합니다.

### 디버그 로그 액세스

1. 왼쪽 사이드바에서 **디버그 로그** <img src="../.gitbook/assets/icon_log.JPG" alt="" data-size="line"> 아이콘을 클릭합니다
2. 실시간 처리 메시지가 표시되는 로그 패널이 열립니다
3. 최신 메시지를 보여주기 위해 자동으로 스크롤됩니다

### 로그 메시지 이해하기

#### 정보 메시지 (흰색/회색)

정상적인 처리 업데이트:

```
[INFO] Processing started
[INFO] Target detected in IMG_0015.RAW - 4 panels found
[INFO] Calibrating IMG_0234.RAW
[INFO] Exported NDVI image: IMG_0234_NDVI.tif
[INFO] Processing complete
```

#### 경고 메시지 (노란색)

처리를 중단시키지 않는 비중요 문제:

```
[WARN] No GPS data found in IMG_0145.RAW
[WARN] Target image timestamp gap > 30 minutes
[WARN] Low contrast in calibration panel - results may vary
```

**조치:** 처리 후 경고를 검토하되, 중단하지 마십시오

#### 오류 메시지 (Red)

처리 실패를 유발할 수 있는 중대한 문제:

```
[ERROR] Cannot write file - disk full
[ERROR] Corrupted image file: IMG_0299.RAW
[ERROR] No targets detected - enable reflectance calibration or mark target images
```

**조치:** 처리를 중지하고, 오류를 해결한 후 다시 시작하십시오

### 일반적인 로그 메시지

| 메시지                          | 의미                                | 필요한 조치                                         |
| -------------------------------- | -------------------------------------- | ----------------------------------------------------- |
| &quot;\[파일명\]에서 타겟 감지됨&quot; | 보정 타겟을 성공적으로 찾음                                         | 없음 - 정상                                         |
| &quot;Y개 중 X번째 이미지 처리 중&quot;        | 현재 진행 상황 업데이트                                         | 없음 - 정상                                         |
| &quot;타겟을 찾을 수 없음&quot;               | 보정 타겟이 감지되지 않음                                         | 타겟 이미지를 표시하거나 반사율 보정을 비활성화하십시오                                         |
| &quot;디스크 공간 부족&quot;        | 출력용 저장 공간 부족          | 디스크 공간 확보                                    |
| &quot;손상된 파일 건너뛰기&quot;        | 이미지 파일이 손상됨                  | SD 카드에서 파일을 다시 복사                             |
| &quot;PPK 데이터 적용됨&quot;               | .daq 파일의 GPS 보정값 적용됨 | 없음 - 정상                                         |

### 로그 데이터 복사

문제 해결 또는 지원을 위해 로그를 복사하려면:

1. 디버그 로그 패널을 엽니다.
2. **&quot;로그 복사&quot;** 버튼을 클릭합니다(또는 마우스 오른쪽 버튼 클릭 → 모두 선택).
3. 텍스트 파일이나 이메일에 붙여넣습니다.
4. 필요한 경우 MAPIR 지원팀에 전송합니다.

## 시스템 리소스 모니터링

### CPU 사용량

**무료 모드:**

* 1개의 CPU 코어가 약 100% 사용
* 다른 코어는 유휴 상태이거나 사용 가능
* 시스템은 정상적으로 반응함

**Chloros+ 병렬 모드:**

* 여러 코어가 80~100% 사용 (최대 16개 코어)
* 전체 CPU 사용률이 높음
* 시스템 반응이 다소 느려질 수 있음

**모니터링 방법:**

* Windows 작업 관리자 (Ctrl+Shift+Esc)
* 성능 탭 → CPU 섹션
* &quot;Chloros&quot; 또는 &quot;chloros-backend&quot; 프로세스 확인

### 메모리(RAM) 사용량

**일반적인 사용량:**

* 소규모 프로젝트 (&lt; 100개 이미지): 2~4 GB
* 중규모 프로젝트 (100~500개 이미지): 4~8 GB
* 대규모 프로젝트 (500개 이상 이미지): 8~16 GB
* Chloros+ 병렬 모드는 더 많은 RAM을 사용합니다

**메모리가 부족할 경우:**

* 더 작은 배치로 처리
* 다른 애플리케이션 종료
* 대규모 데이터셋을 정기적으로 처리하는 경우 RAM 업그레이드

### GPU 사용량 (CUDA를 사용하는 Chloros+)

GPU 가속이 활성화된 경우:

* NVIDIA GPU 사용률이 높게 나타남 (60~90%)
* VRAM 사용량이 증가합니다(4GB 이상의 VRAM 필요)
* 보정 단계가 훨씬 빨라집니다

**모니터링 방법:**

* NVIDIA 시스템 트레이 아이콘
* 작업 관리자 → 성능 → GPU
* GPU-Z 또는 유사한 모니터링 도구

### 디스크 I/O

**예상되는 사항:**

* 분석 단계에서 높은 디스크 읽기
* 내보내기 단계에서 높은 디스크 쓰기
* SSD가 HDD보다 훨씬 빠름

**성능 팁:**

* 가능하면 프로젝트 폴더에 SSD 사용
* 대용량 데이터 세트의 경우 네트워크 드라이브 사용 피하기
* 디스크 용량이 거의 꽉 차지 않았는지 확인 (쓰기 속도에 영향)

## 처리 중 문제 감지

### 경고 신호

**진행이 멈춤(5분 이상 변화 없음):**

* 디버그 로그에서 오류 확인
* 사용 가능한 디스크 공간 확인
* 작업 관리자에서 Chloros가 실행 중인지 확인

**오류 메시지가 자주 나타남:**

* 처리를 중지하고 오류 확인
* 일반적인 원인: 디스크 공간 부족, 파일 손상, 메모리 문제
* 아래의 문제 해결 섹션 참조

**시스템이 응답하지 않음:**

* Chloros+ 병렬 모드가 너무 많은 리소스를 사용 중
* 동시 작업 수를 줄이거나 하드웨어 업그레이드를 고려하십시오
* 프리 모드는 리소스 소모가 적습니다

### 처리를 중지해야 할 때

다음과 같은 증상이 나타나면 처리를 중지하십시오:

* ❌ &quot;디스크 용량 부족&quot; 또는 &quot;파일 쓰기 실패&quot; 오류
* ❌ 이미지 파일 손상 오류가 반복적으로 발생함
* ❌ 시스템이 완전히 멈춤(응답 없음)
* ❌ 잘못된 설정이 적용되었음을 확인함
* ❌ 잘못된 이미지를 가져옴

**중지 방법:**

1.**중지/취소 버튼**(시작 버튼 대신 표시됨)을 클릭하십시오
2. 처리가 중단되며 진행 상황은 사라집니다
3. 문제를 해결하고 처음부터 다시 시작하십시오

## 처리 중 문제 해결

### 처리 속도가 매우 느림

**가능한 원인:**

* 대상 이미지가 지정되지 않음 (모든 이미지 스캔 중)
* SSD 대신 HDD 저장 장치 사용
* 시스템 리소스 부족
* 너무 많은 인덱스 구성
* 네트워크 드라이브 액세스

**해결 방법:**

1. 방금 시작하여 &#x27;탐지&#x27; 단계인 경우: 취소 후 대상 이미지를 지정하고 다시 시작
2. 향후 조치: SSD 사용, 인덱스 수 줄이기, 하드웨어 업그레이드
3. 대용량 데이터셋 일괄 처리를 위해 CLI 사용 고려

### &quot;디스크 공간&quot; 경고

**해결 방법:**

1. 즉시 디스크 공간 확보
2. 프로젝트가 있는 드라이브를 용량이 더 큰 드라이브로 이동
3. 내보낼 인덱스 수 줄이기
4. TIFF 대신 JPG 형식 사용 (파일 크기 감소)

### 빈번한 &quot;파일 손상&quot; 메시지

**해결 방법:**

1. 무결성을 확인하기 위해 SD 카드에서 이미지를 다시 복사
2. SD 카드 오류 검사
3. 프로젝트에서 손상된 파일 제거
4. 나머지 이미지 처리 계속

### 시스템 과열 / 스로틀링

**해결 방법:**

1. 적절한 통풍을 확보하십시오
2. 컴퓨터 통풍구의 먼지를 제거하십시오
3. 처리 부하를 줄이십시오 (Chloros+ 대신 Free 모드 사용)
4. 하루 중 기온이 낮은 시간에 처리하십시오

***

## 처리 완료 알림

처리가 완료되면:

* 진행률 표시줄이 100%에 도달
* 디버그 로그에 **&quot;처리 완료&quot;** 메시지 표시
* 시작 버튼이 다시 활성화됨
* 모든 출력 파일이 카메라 모델 하위 폴더에 있음

4. **처리된 이미지 미리 보기** - 이미지 뷰어 또는 외부 소프트웨어 사용

처리된 결과물의 검토 및 사용 방법에 대한 자세한 내용은 [처리 완료](finishing-the-processing.md)를 참조하십시오.
