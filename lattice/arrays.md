# 멀티 카메라 어레이

LATTICE **어레이**는 두 대 이상의 LATTICE 카메라를 하나의 동기화된 단위로 연결한 것입니다. 이 중 한 대의 카메라가**마스터**역할을 하며, 공유된 동기화 라인(기본값**Line2**)을 통해 하드웨어 GPIO 트리거 펄스를 발생시킵니다. 이를 통해 모든 구성원이 동일한 순간을 촬영합니다. Chloros는 PTP 시간 동기화, 라이브 미리보기(카메라별 타일 또는 정렬된 단일 다중 대역 합성 이미지), 그리고 동기화된 캡처 기능을 제공합니다. 각 캡처 패스마다 하나의 **프레임 그룹**이 생성되며, 이 그룹 내의 모든 카메라는 동일한 타임스탬프와 프레임 ID를 공유합니다 (캡처 출력 시 `fid:N`로 표시됨).

어레이는 모노(M3M) 카메라가 식생 지수를 생성하는 방식입니다. 하나의 카메라가 하나의 밴드를 제공하면, 어레이가 이를 정렬하여 다중 밴드 스택으로 만듭니다. [모노 카메라 및 식생 지수](mono-indices.md)를 참조하십시오.

어레이를 연결하는 데는 세 가지 동등한 방법이 있으며, 이들 모두 동일한 “스마트 준비(smart-prep)” 흐름을 실행합니다:

| 표면 | 진입점 |
| --- | --- |
| GUI | 카메라 탭 → **어레이 연결** (파란색 버튼) |
| CLI | `chloros-cli lattice array-connect --serials SN1,SN2,…` (첫 번째 일련번호 = 마스터) |
| Python SDK | `connect_array(serials=[…])` → `ArraySession` (첫 번째 일련번호 = 마스터) |

Smart-prep은 다음 작업을 수행합니다: 네트워크 기능 탐색(ICMP DF 핑 + GVSP 탐색), 동기화 계층 선택, 요청된 프레임 크기에 대한 프레임 속도 예측, 압축된 12비트 전송 방식 결정 ([압축된 12비트 전송](#packed-12-bit-transport) 참조), PTP 활성화, 카메라별 픽셀 형식 자동 선택, 각 카메라의 저장된 상태를 기반으로 한 자동 노출 초기화, Line2의 GPIO 트리거 구성 등을 수행합니다.

**기본값은 전체 센서입니다 (1.3.0에서 새로 추가됨).** Connect는 사용자가 요청한 프레임 크기를 유지합니다. 별도로 선택하지 않는 한, 전체 2048×1536 센서 해상도를 사용하며, 비닝이나 크롭을 적용하지 않고 — 프레임 속도는 호스트와 네트워크가 제공하는 수준까지 낮아집니다. Connect는 절대 자체적으로 비닝이나 크롭을 수행하지 않습니다(1.2.0 버전에서는 1.5 fps 미만일 때 자동으로 비닝이 적용되었습니다). 비닝이나 더 작은 ROI 적용 여부는 사용자가 결정합니다. 연결 대화 상자에서 하나를 선택하면 ‘예상 결과’에 해당 설정으로 얻을 수 있는 프레임 속도가 표시되며, `array-connect`는 더 빠른 옵션과 예상 프레임 속도를 출력합니다.

{% hint style="info" %}
이 모든 기능이 작동하려면 링크를 통해 카메라에 접근 가능해야 합니다 — [카메라 연결](connecting.md)를 참조하십시오. 다중 카메라 리그의 경우, 호스트 NIC의 수신 링 설정은 링크 속도만큼 중요합니다. 전체 증상→해결 방법 표는 [CLI 참조 § 호스트 NIC 설정 및 튜닝](../reference/cli-reference.md#host-nic-setup--tuning-lattice-arrays)에 있습니다.
{% endhint %}

## 어레이 연결 대화 상자

카메라 탭 → **어레이 연결**을 선택하면**선택 → 디스플레이 모드 → 설정**의 3단계 마법사가 열립니다.

### 1단계 — 마스터 및 슬레이브 선택



<!-- SCREENSHOT-NEEDED: Array Connect dialog, Select scene, with 3-4 LATTICE cameras discovered (an FRGB among them). Table showing Camera / Serial / IP / Master radio / Slave checkbox columns in camera order (M3C first, FRGB at the top), with the FRGB pre-selected as master and the green "Sync cable found on N cameras. Any of them can be master; the RGB camera (else the first) is pre-selected." probe banner visible above the table. -->

대화 상자가 열리자마자 네트워크를 스캔한 후("네트워크 스캔 중..."), 동기화 케이블을 탐색("동기화 케이블 탐색 중...")하여 M8 동기화 라인에 연결된 카메라를 찾습니다. 어레이를 구성하려면 최소 **2대의 카메라**가 필요합니다.

M8 동기화 케이블은 하나의 접속점에서 합쳐지므로, **케이블이 연결된 카메라라면 어느 것이든 마스터가 될 수 있습니다**가 될 수 있습니다. 탐색 기능은 역할을 미리 지정합니다. 즉, RGB (`-FRGB`) 카메라가 케이블로 연결된 경우 마스터로, 그렇지 않은 경우 가장 먼저 케이블로 연결된 카메라를 마스터로, 나머지 케이블로 연결된 카메라들은 슬레이브로 지정하며, 다음 세 가지 배너 중 하나를 표시합니다:

| 배너 | 의미 |
| --- | --- |
| "{n}대의 카메라에서 동기화 케이블이 감지되었습니다. 이들 중 어느 것이든 마스터가 될 수 있으며, RGB 카메라(그렇지 않으면 목록의 첫 번째 카메라)가 미리 선택되어 있습니다." (녹색) | 프로브가 동기화 라인에서 카메라를 감지했으며, 마스터 및 슬레이브 확인란이 이미 선택되어 있습니다. |
| "마스터 감지되지 않음 - GPIO 케이블 확인" (주황색) | 트리거 펄스를 감지한 카메라가 없습니다. 싱크 케이블 연결 상태를 확인하십시오. 역할은 여전히 미리 설정되어 있으며(RGB 카메라, 없으면 목록의 첫 번째 카메라가 마스터로 지정됨), 이를 변경할 수 있습니다. |
| "싱크 케이블 없음: {serials}" (주황색) | 나열된 카메라에 싱크 케이블이 연결되어 있지 않습니다. |

카메라 표에는 **카메라 / 시리얼 / IP / 마스터(무선) / 슬레이브(체크박스)**열이 있습니다. 행은**카메라 순서**대로 나열됩니다 — M3C(바이엘) 카메라가 M3M(모노)보다 먼저 표시되며, M3C 내에서는 FRGB, FRGN, FOCN, FNGB 순으로, M3M은 필터 파장 순서대로, 가장 낮은 값부터 먼저 나열됩니다(F450이 F808보다 먼저). 사이드바의 카메라 목록과 그리드의 기본 레이아웃은 동일한 순서를 따릅니다.

* **마스터**를 정확히**하나**,**슬레이브**를**하나 이상** 선택하십시오. 현재 마스터의 라디오 버튼을 다시 클릭하면 선택이 해제됩니다. 다른 마스터를 선택하는 데는 클릭 한 번이면 충분합니다. 새로운 마스터가 슬레이브 목록에서 빠져나가고, 이전 마스터는 슬레이브가 됩니다(동기화 케이블이 없는 경우는 제외).
* **"동기화 케이블 없음"**으로 표시된 카메라는 절대로 슬레이브로 선택할 수 없습니다. 트리거 배선이 없는 슬레이브는 동기화 라인을 무한정 대기하게 되어 무효한 영상을 전송하게 됩니다. 대신 해당 카메라를 독립형 카메라로 연결하십시오.
* 이미 독립형으로 연결된 카메라는 *비활성화*되지 않습니다. 어레이 연결 시 독립형 세션이 해제되고, 해당 카메라는 어레이 내에서 다시 열립니다.

**다음: 디스플레이 모드 →**는 마스터 1대와 슬레이브 1대 이상이 선택되면 활성화됩니다.**재스캔**은 탐색 및 배선 프로브를 다시 실행합니다.

{% hint style="warning" %}
**취소**는 스캔이나 프로브가 진행 중일 때는 비활성화됩니다. 프로브 도중 취소하면 LATTICE 카메라 펌웨어에서 카메라 SDK가 충돌할 수 있습니다. 로딩 아이콘이 완료될 때까지 기다리십시오.
{% endhint %}

### 2단계 — 표시 모드

<!-- SCREENSHOT-NEEDED: Array Connect dialog, Display Mode scene, showing the two selectable cards ("Separate Cameras" and "Combined Cameras") with Combined selected/highlighted as the default. -->



| 모드 | 결과 |
| --- | --- |
| **별도 카메라** | 카메라당 하나의 라이브 타일이 표시되며, 모든 카메라가 동시에 트리거되어 프레임이 동기화됩니다. 각 카메라는 고유한 색상과 설정을 유지합니다. |
| **결합된 카메라** *(기본값)* | 정렬된 다중 대역 NDVI/지수 합성 이미지를 렌더링하는 단일 타일. 카메라들은 어레이 색상을 공유합니다. |

표시 모드는 라이브 미리보기의 표시 방식만 변경하며, 캡처 동작은 두 모드 모두 동일합니다.

### 3단계 — 어레이 설정 및 예상 결과

<!-- SCREENSHOT-NEEDED: Array Connect dialog, Settings scene, healthy state: left column with ROI / Binning / Trigger Rate / Wire Budget controls (1.3.0 has no "Pin resolution" checkbox), right "Projected Outcome" column showing green "Simultaneous capture" tier, an fps range, the NIC line, the "Sim-emit burst" line, and the "Wire budget" line with a checkmark. -->



이 화면으로 진입하면 Chloros는 백엔드에 **권장 사항**을 요청하여 이를 적용합니다:**호스트와 통신 회선이 제공하는 어떤 프레임 속도에서도 감당할 수 있는 한, 전체 센서(비닝 없음, ROI 자르기 없음)**를 사용합니다. 전체 센서를 처리할 수 있는 속도가 없을 때만 권장 사항에 따라 프레임을 축소하며, 이때는 ROI 자르기보다 비닝을 우선시하는데, 비닝이 전체 시야를 보존하기 때문입니다. 이 시점부터는 해상도를 희생하여 프레임 속도를 확보하게 됩니다. 설정을 변경할 때마다 분석이 실시간으로 재실행되며, 오른쪽의**예상 결과** 패널이 업데이트됩니다.

왼쪽 열 — 설정:

| 제어 | 선택 사항 | 기본값 | 참고 |
| --- | --- | --- | --- |
| **ROI (시야)** | 전체 (2048×1536) / 절반 (1024×768) / 1/4 (512×384) | 전체 | 센서 자르기: 네이티브 픽셀 피치에서 더 작은 영역으로 절반/1/4 자르기. |
| **비닝** | 1× / 2× (2×2 합산) / 4× (4×4 합산) | 1× | 하드웨어 비닝: 2×2 = 와이어 비용의 1/4로 전체 FoV 확보; 4×4 = 1/16의 비용으로 전체 FoV 확보. 카메라가 비닝을 지원하지 않으면 숨김. |
| **와이어 측 이미지** (리드아웃) | — | — | 비닝 후 실제로 와이어를 통해 전송되는 너비×높이이며, 16의 배수(최소 64)로 반올림됨. |
| **트리거 속도** | 0.5–60 fps, 단계 0.1 | 비워두면 자동 | 마스터의 트리거 발사 속도. Chloros가 자동으로 계산하도록 비워 둡니다. |
| **전송 대역폭**| 20–2000 MB/s, 단계 10 | 비어 있음 = 자동 | 호스트가 실제로 처리할 수 있는 양(MB/s 단위) —**전체 어레이 할당이 이 수치에 달려 있습니다.** 네트워크 어댑터에서 자동으로 감지됩니다. 어레이에서 손상된 프레임을 보고할 경우 이 값을 낮추십시오. 감지된 값은 USB 어댑터와 공유 스위치의 실제 성능을 과대평가하는 경향이 있습니다. 이 값을 변경하면 예측이 실시간으로 다시 실행됩니다. 이 필드는 마지막으로 연결되었던 어레이의 대역폭(프로젝트와 함께 저장됨)으로 열리므로, 한 번 수정한 대역폭 값은 유지됩니다. |

1.2.0 버전에서 제공되던 **핀 해상도** 확인란이 사라졌습니다. 연결 시에는 사용자가 선택한 프레임 크기를 항상 유지하며, 대신 프레임 속도를 낮춥니다.

오른쪽 열 — **예상 결과**:

* **동기화 단계** — “동시 캡처”(녹색), “동시 캡처(FTD-시차 방출)”(녹색), “시차 캡처(100 ms 드리프트)”(황색), 또는 “구성이 너무 큼” (빨간색). Chloros는 계층을 선택합니다: 카메라 속도를 맞출 수 있는 속도로 와이어를 공유할 수 있을 때는 항상 동시 캡처를 선택하고(각 카메라의 할당량이 줄어들수록 프레임 속도는 떨어집니다), 그렇지 않을 때는 시차 캡처만 선택합니다. 따라서 어레이는 어떤 네트워크에서든 해당 네트워크가 허용하는 프레임 속도로 연결됩니다.
* **fps 예상치** — 어레이가 작동할 것으로 예상되는 프레임 속도입니다. 동시 캡처의 경우 단일 수치로 표시됩니다: 프레임 속도가 우선 적용되며, 자동 노출이 주어진 기간을 채운 다음 게인을 높여 어두운 장면에서도 프레임 속도가 떨어지지 않도록 합니다([자동 노출이 노출 시간과 게인을 어떻게 배분하는지](camera-settings.md) 참조). 시차 캡처의 경우, 어두운 장면에서는 각 카메라의 노출 시간이 길어짐에 따라 시차가 늘어나기 때문에 범위로 표시됩니다("어두움 → 밝음").
* **NIC 라인** — 링크 속도와 지속 전송량("NIC {mbps} Mbps · 지속 {N} MB/s").
* **동시 송신 버스트 확인** — 호스트의 NIC 수신 링이 모든 카메라에서 동시에 발생하는 버스트를 처리할 수 있는지 여부("동시 송신 버스트: X MB · NIC 링 사용 가능: Y MB ✓/✗").
* **선로 용량 점검** — 정상 상태의 총 수요와 충돌 방지 선로 상한선 비교 (“선로 용량: {n} 대의 카메라가 요구하는 {demand} MB/s · 상한선 {ceiling} MB/s ✓/✗ 초과 할당”).
* **"이 회선의 최대 카메라 수: {n} — 카메라당 대역폭 하한에 의해 설정되므로, 비닝을 해도 이 수치는 증가하지 않습니다."** — 카메라 수 상한에 근접했거나 초과했을 때 표시됩니다.
* **"이 설정에서는 프레임이 손실됩니다."**— 백엔드에서 제시한 사유와 함께 빨간색 경고가 표시되며, 차단 요인 목록과 파란색**해결 방법**("이 어레이를 네트워크에 맞추려면" / "동시 캡처를 활성화하려면")이 제공됩니다.**적용 및 연결**은 예측치가 생성될 때까지 잠겨 있으며, 레이블을 통해 거부 사유를 확인할 수 있습니다:

| 버튼 레이블 | 의미 | 실제로 도움이 되는 조치 |
| --- | --- | --- |
| "분석 중..." | 분석이 아직 진행 중입니다. | 기다리세요. |
| **"이 네트워크에 카메라가 너무 많습니다"**| 이 네트워크는 한 번에 카메라 한 대조차 처리할 수 없습니다(집계 검사 실패): 처리 가능한 속도보다 훨씬 많은 카메라가 있거나, 다른 카메라가 동시에 스트리밍 중입니다. | 카메라 수를 줄이거나, 종단 간 점보 프레임을 사용하거나, 더 빠른 NIC를 사용하세요.**ROI를 줄여도 소용없습니다** — 아래 참조. |
| **"ROI를 줄여야 활성화됩니다"** | 이 설정에서는 프레임이 누락됩니다(버스트/링 검사 실패). | ROI를 줄이거나, 비닝을 높이거나, NIC 수신 링을 수정하십시오. |

연결 중에 시리얼별 진행률 표시줄이 있는 녹색 **보정 데이터 다운로드 패널**이 나타날 수 있습니다. 컴퓨터에 카메라를 처음 연결할 때, Chloros는 GigE를 통해 카메라에서 약 3.8 MB 크기의 공장 보정 팩을 가져옵니다(카메라당 약 70초 소요). 캐시된 카메라에는 이 패널이 표시되지 않으며, 카메라가 6대 이상일 경우 행이 스크롤됩니다. [카메라 연결](connecting.md)을 참조하십시오.

### 압축된 12비트 전송

12비트 형식(`BayerRG12`, `Mono12`)은 일반적으로 16비트 워드로 전송됩니다. **압축**전송 방식은 동일한 12비트를 픽셀당 1.5바이트로 전송하고 호스트에서 압축을 해제하므로, 각 프레임 전송 시간이 25% 단축됩니다. 센서 최대 부하 시 초당 프레임 수가 약 3분의 1 정도 증가합니다.**저장된 데이터는 동일합니다.** Array Connect는 이를 자동으로 결정합니다(`auto`): 압축이 도움이 되고 호스트에 압축 해제를 처리할 여유 CPU가 있을 때만 압축합니다. GUI에는 이에 대한 설정 옵션이 없으며, CLI에서는 `array-connect --packed {auto,on,off}` (기본값: `auto`)를 사용하십시오. 8비트 및 16비트 형식은 절대 압축되지 않습니다.

## 대역폭: 수용 가능한 카메라 수

어레이가 처리할 수 있는 용량은 클로로스(Chloros)가 아닌 회선(wire)의 특성에 따라 결정되므로, 계획에 필요한 수치는 하드웨어 설명서에 나와 있습니다: **[어레이 대역폭 계획](https://mapir.gitbook.io/lattice-camera/setup/array-bandwidth-planning)**.

Chloros가 이를 어떻게 처리하는지: 연결 대화 상자는 네트워크 프로브를 실행하여 달성 가능한 프레임 속도를 예측하고, 이에 맞는 티어를 선택합니다. 어레이는 어떤 네트워크에서도 연결됩니다. 속도가 느린 링크에서는 어레이가 거부되거나 프레임이 축소되는 대신, 각 카메라가 회선 대역폭의 할당량에 맞춰 속도가 조절되며 프레임 속도가 떨어집니다. 해당 회선이 한 번에 카메라 한 대조차 처리할 수 없는 어레이만 거부되며(**이 네트워크에 카메라가 너무 많습니다**), 패킷이 아무런 경고 없이 삭제되지는 않습니다 — 앞서 설명한 예상 결과 패널을 참조하십시오.

## 프레임이 누락될 때

카메라가 게시된 그룹에서 누락되는 데는 완전히 다른 두 가지 이유가 있을 수 있으며,
각각에 대해 정반대의 해결책이 필요합니다. Chloros는 두 가지 이유를 모두 명시하지 않은 하나의
"불완전한" 수치를 보고하는 대신, 이를 별도로 집계합니다:

| 발생한 상황 | 의미 | 확인 대상 |
| --- | --- | --- |
| **손상됨**— 프레임이 도착했으나 구조적으로 결함이 있음 | 네트워크 경로상의 GVSP 패킷 손실 |**선로 용량**, NIC 수신 링, 점보 프레임, 스위치 |
| **도착하지 않음**— 프레임이 전혀 도착하지 않음 | 카메라가 작동하지 않았거나, 카메라에서 데이터가 전송되지 않음 |**M8 동기화 케이블**, 동기화 라인, 모든 구성원이 작동 상태인지 여부 |

어레이가 스트리밍되는 동안 분할 상태는 10초마다 재평가됩니다. 5%를 초과하면
두 수치가 모두 명시된 상태로 기록되며, 각 카메라별로 손상된 버퍼는 처음 발생했을 때
보고된 후, 긴 세션에서도 가독성을 유지할 수 있도록 1분마다 집계됩니다.

**‘도착하지 않음’이 0인 손상된 프레임은 트리거링과 케이블 동기화가 완벽하다는 뜻**이며,
모든 손실된 프레임은 네트워크 경로에서 발생합니다. 해결 방법은 **Wire Budget**을 낮추고
다시 연결하는 것입니다.

{% hint style="warning" %}
**트리거 속도를 낮추는 것은 손상된 프레임 문제 해결에 도움이 되지 않습니다.** 카메라의 패킷
페이싱은 연결 시 한 번만 설정됩니다. 트리거 속도를 낮추면 버스트가 발생하는 빈도는
변화하지만, 버스트 자체가 네트워크로 전송되는 속도는 변하지 않습니다. 측정된 4대 카메라 시스템에서
트리거 속도를 5배로 줄여도 아무런 변화가 없었으나, 와이어 예산을 240에서
200 MB/s로 줄였을 때는 같은 시스템의 손상률이 10.4%에서 0%로 떨어졌습니다.
{% endhint %}

실행 중인 어레이는 자체적으로 재계획을 수립할 수 없습니다. 연결을 끊고 다시 연결해야 연결 시점
선택기가 새로운 예산에 맞춰 작동할 수 있습니다.

### USB 네트워크 어댑터의 속도 제한

USB 이더넷 어댑터는 *이더넷* 링크 속도를 표시하지만, 실제로
유지할 수 있는 속도는 USB 버스 및 해당 드라이버에 의해 제한됩니다. USB 10GbE 동글은 과거에
대략 1000 MB/s의 처리량 — 실제로 측정된 적이 없는 수치였습니다 — 이 유령 같은 여유 용량을 기준으로
4대의 카메라를 동기화시키자 프레임의 6~18%가 손상되었으나, 어레이는
여전히 정상적인 목표 프레임 속도를 보고했습니다. 현재 USB 연결 어댑터의 상한선은
Windows 및 NVIDIA Jetson에서는 **200 MB/s**, Linux x86_64에서는 **400 MB/s**로 제한됩니다. 이 상한은 백분율이 아닌 절대값입니다. 왜냐하면 제한 요소는
버스 자체이기 때문입니다. USB 1 GbE 어댑터는 약 80 MB/s의 속도를 내며 이 제한의 영향을 받지 않습니다.

호스트의 속도가 제한값보다 실제로 더 빠르다면, **Wire Budget**을 높여 이를 반영하십시오.

## PTP 시간 동기화

프레임 *동기화*는 하드웨어 트리거를 통해 이루어지며, **PTP**(IEEE 1588 PTPv2)는 모든 장치에 걸쳐 일관된 *타임스탬프*를 제공합니다. 이 기능은 어레이 연결 시 기본적으로 활성화됩니다:

* **Chloros** 호스트 백엔드가 PTP 그랜드마스터를 실행합니다. LATTICE 카메라와 DAQ-E 광 센서는 도메인 0에서 이에 종속되므로, 이미지 타임스탬프와 DAQ 스펙트럼은 하나의 클럭(~1 ms)에 맞춰집니다.
* `--no-ptp` (CLI) 명령을 사용하면 벤치 작업 시 이 기능이 비활성화되며, 이 경우 카메라 간 타임스탬프는 **비교할 수 없습니다**.
* CLI를 통해 동기화 상태를 확인하십시오:

```bash
chloros-cli time-sync status     # grandmaster state, clock identity, health (OK, or why its packets are not reaching the network)
chloros-cli time-sync peers      # slaves seen (cameras + DAQ-E sensors)
chloros-cli time-sync cameras    # per-camera PtpStatus / PtpOffsetFromMaster / PtpMeanPathDelay
```

'카메라(Cameras)' 탭 자체에는 PTP 표시기가 없습니다. 해당 탭에서 확인할 수 있는 카메라별 동기화 정보는 읽기 전용인 **역할(Role)**(마스터/슬레이브),**동기화 라인(Sync Line)**, 그리고 어레이의**기능(Capabilities)** 계층입니다. DAQ-E의 PTP 상태는 '광 센서(Light Sensors)' 탭의 센서 세부 정보에서 확인할 수 있습니다.

**별도 모드**에서는 카메라당 하나의 타일이 표시됩니다. 각 타일에는 다음이 오버레이됩니다:

* 카메라 이름(왼쪽 상단),
* **fps 표시**(오른쪽 상단) — 이는 백엔드에서 보고하는 카메라의 *실제 캡처 속도*이며, 미리보기 폴링 속도가 아닙니다(라이브 미리보기는 캡처 속도와 관계없이 30 fps로 제한됨),
* 상태 표시점 — 녹색(스트리밍 중) / 주황색(로딩 중) / 빨간색(오류),
* 2초 동안 새로운 프레임이 도착하지 않았을 때 표시되는 **오래된 프레임 스핀너** — 백엔드가 카메라 간 통신 대역폭을 재조정하는 동안, 연결/분리 후 약 5초 동안은 정상적인 현상입니다.**결합 모드**는 단일 합성 타일을 표시합니다: 백엔드는 디베이어링, 크기 조정, 정렬, 노이즈 제거를 수행하고, 대역별 복사도(라이트 센서가 바인딩된 경우 DLS 반사도 포함)로 변환한 뒤, 배열의 인덱스 표현식을 평가하고, LUT를 적용하고, 결과를 MJPEG로 스트리밍합니다. 첫 번째 정렬된 프레임이 렌더링될 때까지 타일에는 현재 상태가 표시됩니다: "어레이 준비 중…", "정렬 보정 중…", "첫 번째 프레임 대기 중…", 또는 — 타일의 자동 정렬 재시도(약 1분) 시간이 초과된 경우 —**정렬 보정** 버튼과 함께 "정렬 필요"를 표시합니다.

어레이 타일의 fps 표시창은 스트림의 상태도 알려줍니다: 설정 변경(포맷, 비닝, ROI)으로 인해 카메라가 재시작되는 동안에는 **"설정 적용 중…"**, 어레이가 작동 중이지만 프레임 그룹 전송이 중단된 경우에는**"정지됨"**, 스트리밍이 중단된 경우에는**"중지됨"**은 스트리밍이 중단되었음을 의미합니다. 이 경우 어레이를 다시 연결하십시오. 스펙트럼 언믹스 과정에서 합성 이미지에 표시된 밴드의 픽셀 상당 부분(25% 이상)에서 클램핑이 필요한 경우, 타일에는**"신뢰도 낮은 밴드 데이터 · N%"**라고 표시됩니다: 해당 밴드를 기반으로 산출된 인덱스 값은 신뢰할 수 없습니다(일반적으로 한 밴드가 빛을 너무 적게 수신한 경우).

결합 모드에 대한 유용한 정보:

* 합성 이미지는 **마스터**카메라의 프레임에 정렬됩니다. 합성 이미지에서 AE-ROI 조준 및 스팟 측광은 마스터 카메라에 대해서는 정확하지만 슬레이브 카메라에 대해서는 대략적입니다. 추가 카메라 연결을 열지 않고도 카메라별 픽셀 단위의 정확한 타일을 보려면**Split View**(어레이 설정 → "구성원 카메라 표시")를 사용하십시오.
* **디스플레이 레이어** (어레이 설정; 기본값: 꺼짐)를 사용하면 전경 및 배경 레이어를 선택할 수 있습니다. 구성원 카메라 또는**인덱스** 중 어느 것이나 선택 가능합니다. 전경 = 인덱스로 설정하면 LUT 최소/최대 범위를 벗어난 픽셀에는 배경 레이어가 표시됩니다.
* **렌더 해상도**(기본값 720p)는 라이브 스트림의 높이 *및* 저장된 합성 이미지의 내보내기 크기를 설정합니다. 카메라별 이미지는 항상 전체 해상도로 내보내집니다.
* 정렬은 세션별로 계산되며 절대 저장되지 않습니다. Chloros는 **두 디스플레이 모드 모두에서 연결 후 구성원들의 자동 노출이 안정화되면 모든 어레이를 자동으로 정렬합니다**(최대 5분 동안 계속 시도합니다). 어레이 설정 패널의**정렬**섹션에는 RMS 잔차와**정렬 재보정** 버튼이 표시되며, 이는 합성 타일이 없는 개별 어레이에도 적용됩니다.

## 캡처: 모니터링 대 분석

어레이 캡처 영역은 **모니터링 등급**(보이는 대로 기록)과**분석 등급**(원시 데이터 기록, 나중에 보정)으로 명확하게 구분됩니다:

| 워크플로 | 등급 | 저장 내용 | GUI | CLI |
| --- | --- | --- | --- | --- |
| **캡처**(스틸 이미지) | 분석 | 패스당 동기화된 프레임 그룹 1개; 선택한 모든 내보내기 수준(원본/데베이어링/방사도/반사도/미리보기/인덱스)의 카메라별 파일 + `.daq` 사이드카 |**모두 캡처** 버튼 + 캡처 설정 | `lattice array-capture` |
| **인덱스 비디오 기록** | 모니터링 | 표시된 대로 실시간 결합 인덱스 합성 영상 — 8비트, 미리보기 해상도, LUT 적용됨. GUI 창이 열려 있지 않은 상태에서 CLI를 통해, 배열이 정렬되면 백엔드가 배열의 NDVI (또는 `--expr`)를 렌더링합니다. 프레임을 기록하지 않는 경우 기록이 실패합니다 | ● 인덱스 비디오 기록 (결합된 어레이) | `lattice array-record` |
| **원시 버스트 → 동영상 생성**| 분석 | 전체 캡처 속도의 원시 센서 프레임 + 매니페스트 + `.daq`, 이후 DAQ 측정값과 시간 동기화된 보정된 복사도/반사도/지수 동영상으로 오프라인 재구성 | ⦿ 원시 버스트 기록 →**동영상 생성** | `lattice array-burst` → `lattice array-build-video` |

경험적 규칙: 픽셀 데이터가 *측정값*으로 활용될 경우, 캡처 또는 버스트(분석 등급)를 사용하십시오. 어레이가 포착한 내용을 단순히 *확인하거나 시연*하기만 하면 되는 경우, 인덱스 비디오(모니터링 등급)를 기록하십시오.

### 캡처 설정 (GUI)



<!-- SCREENSHOT-NEEDED: Capture Settings pane (gear next to Capture All) with a connected array: capture-mode buttons (Single/Continuous/Interval), the bulk export-type toggle row, the Fastest Capture toggle, and the per-array group card showing the Aligned checkbox and the "Record index video" / "Record raw burst" buttons. -->

**Capture All** 옆의 톱니바퀴 아이콘을 클릭하면 캡처 설정 창이 열립니다(프로젝트가 열려 있어야 함 — 캡처된 데이터는 해당 프로젝트에 저장됨):

* **캡처 모드**:**단일**(한 번의 패스) /**연속**(연속 촬영; 캡처 횟수(기본값 1) 또는 시간(기본값 10초)으로 제한됨) /**간격** (타임랩스: X 간격마다 N 장을 촬영하여 총 Y 장을 촬영, 기본값은 5초마다 1장씩 1분 동안).
* **카메라별 내보내기 유형**: Raw, Debayered, Radiance, Reflectance, Preview, Index — 적용 가능한 모든 항목은 기본적으로 활성화되어 있습니다. Radiance/Reflectance는 RGB 필터 카메라의 경우 숨겨집니다; **반사율은 카메라에 DAQ 광 센서가 있을 때만 표시됩니다**(자체 센서이거나 어레이에서 상속받은 경우); 인덱스(Index)를 사용하려면 구성된 인덱스 표현식이 필요합니다.
* **정렬**(어레이별, 기본값**켜짐**): 구성원 내보내기 파일을 어레이의 정렬 프로필에 맞춰 왜곡하여 픽셀 단위로 정렬된 상태로 내보냅니다. Raw는 항상 워핑되지 않은 상태로 유지되지만 메타데이터에 변환 정보를 포함합니다. 어레이 구성원 파일은 각 카메라의 기본 방향으로 저장되며(미러/회전 설정은 적용되지 않고 파일에 기록됨).
* **가장 빠른 캡처** (토글): 원본 전용 + 할당된 DAQ 판독값 + 무료 결합 인덱스 합성값으로, 캡처 시 보정 계산을 건너뛰어 최대 속도를 보장합니다. 저장된 `.daq` 파일을 사용하여 나중에 방사도/반사도/인덱스를 재구성할 수 있습니다.
* 선택 항목은 프로젝트와 함께 유지됩니다. 숨겨지거나 일시 중지된 카메라는 건너뜁니다.
* 어레이에서 **연속** 모드는 Chloros 백엔드 내에서 실행됩니다(1.3.0부터 추가됨): 목록에 있는 모든 카메라가 어레이에 속할 경우, 백엔드가 직접 캡처 루프를 실행하며, 한 그룹을 기록하는 동시에 다음 그룹을 선택하므로 캡처마다 별도의 요청이 발생하지 않습니다. 드라이브 용량이 가득 차면 실행이 중지됩니다("중지됨: 드라이브 용량 부족. N개 저장, F개 실패"). 높은 캡처 속도에 대한 Microsoft Defender 관련 참고 사항은 [캡처 설정 및 모드](capture.md#capture-modes)를 참조하십시오.

이에 상응하는 CLI (동일한 백엔드 엔드포인트, 동일한 동작 방식):

```bash
# One synced group, every applicable export level per camera (the default)
chloros-cli lattice array-capture -o output/

# Interval timelapse: one reflectance pass every 10 s for 5 minutes
chloros-cli lattice array-capture --interval 10 --duration 300 --processing reflectance -o timelapse/

# Fastest grab for a moving rig — raw + .daq now, calibrate later
chloros-cli lattice array-capture --fastest -o flightline/

# 30-second monitoring clip of the combined index view, plus a GIF
chloros-cli lattice array-record --duration 30 --fps 10 --gif -o monitoring/

# 5-second analysis-grade raw burst, then build the combined index video
chloros-cli lattice array-burst --duration 5 --build --products combined:index --fps 10 -o capture/
```

캡처용 TIFF압축은 `deflate`(무손실, 기본값) 또는 `none`입니다. 전체 플래그 테이블, 캡처 폴더 구조 및 재처리 규칙은 [CLI 참조](../reference/cli-reference.md#capture-modes-recorders--offline-reprocess)에 나와 있습니다.

## DAQ 광 센서 페어링

반사율 및 조도 보정된 미리보기를 표시하려면 **광 센서** 탭에 연결된 DAQ 센서에서 하향광 데이터가 필요합니다:

* 사이드바의 **어레이 행**에는**"DAQ · 켜기/끄기" 버튼**이 표시됩니다. 어레이 수준의 광 센서가 설정되어 있거나 구성원 카메라 중 하나라도 자체 광 센서를 가지고 있으면 *켜짐* 상태가 되며, 툴팁에는 어떤 센서가 어떤 카메라에 데이터를 제공하는지 정확히 나열됩니다.
* 어레이 설정 → **주변광 센서**→**광 센서** 드롭다운 메뉴에서 어레이 전체에 적용할 센서를 지정합니다. 이 선택 사항은 프로젝트와 함께 유지되며 모든 구성 카메라에 적용되지만, 개별 카메라는 자체 센서를 사용하여 이 설정을 재정의할 수 있습니다.
* 그 아래의 상태 줄에는 실시간 상태가 표시됩니다: **Off**→ "첫 번째 스펙트럼 대기 중…" →**"활성 — 어레이 내 모든 카메라의 조도가 보정됨"** → 또는, 지난 3초 동안 새로운 스펙트럼이 도착하지 않은 경우, 오래된 데이터 알림 — 마지막 측정값이 계속 사용됩니다(캡처 경로에서는 측정값이 만료되지 않습니다).

센서가 할당된 경우: 반사율 내보내기 유형을 사용할 수 있게 되며, 실시간 미리보기가 조도 보정되고, 예측 자동 노출이 스펙트럼을 활용할 수 있으며, 모든 반사율 캡처 시 실제로 사용된 DAQ 측정값이 **`.daq` 파일**로 캡처의 `daq/` 폴더에**`.daq` 파일**로 저장되므로, 나중에 캡처를 재처리할 수 있습니다. 그 옆에는 해당 측정값이 설명하는 프레임을 가진 카메라의 이름을 나타내는 `.daq.cameras.json` 파일이 있습니다. 재처리 시, Chloros는 해당 카메라의 이미지와만 측정값을 매칭합니다.

## `array-connect` CLI 옵션

| 플래그 | 기본값 | 설명 |
| --- | --- | --- |
| `--serials SN1,SN2,…` | 모든 LATTICE 카메라 자동 탐지 (2대 이상 필요) | **첫 번째 일련번호가 MASTER입니다.** |
| `--line {Line0,Line2,Line3}` | `Line2` | GPIO 동기화 라인. |
| `--target-fps F` | auto | 마스터 트리거 발사 속도. |
| `--binning {1,2,4}` | auto | 하드웨어 비닝. 'auto'는 프레임 속도가 이를 지원하는 경우 전체 센서(비닝 없음)를 사용하며, 'connect'는 속도를 유지하기 위해 비닝을 절대 수행하지 않습니다. |
| `--packed {auto,on,off}` | `auto` | [압축된 12비트 전송](#packed-12-bit-transport): `auto`는 압축이 도움이 되고 호스트가 압축 해제를 감당할 수 있을 때만 압축합니다. |
| `--force-tier {sim-capture-sim-emit, sim-capture-ftd-stagger, slip-emit-and-capture}` | 자동 | 동기화 계층 선택기의 전문가용 재정의. |
| `--wire-ceiling-mbps MB_PER_S` | 자동 감지 | 호스트 와이어 예산(MB/s) — **와이어 예산** 필드의 CLI 형식입니다. 어레이에서 손상된 프레임을 보고하는 경우 이 값을 낮추십시오. 프로젝트와 함께 저장되므로, 나중에 다시 연결하면 이 값이 복원됩니다. |
| `--no-recommend` | off | 네트워크 분석 단계를 건너뜁니다. |
| `--no-ptp` | off | PTP를 비활성화합니다(이 경우 카메라 간 타임스탬프를 비교할 수 없음). |

`lattice array-list`, `array-status` 및 `array-disconnect`는 지속적 세션을 관리합니다. 정렬(`align-calibrate` / `align-apply`) 및 네트워크 툴링을 포함한 전체 하위 명령어 참조는 [CLI 참조 § chloros-cli lattice](../reference/cli-reference.md#chloros-cli-lattice)에 수록되어 있으며, 이에 상응하는 SDK 명령어(`connect_array`, `ArraySession`, `attach_array`, `analyze_array_network`)는 [SDK 참조](../reference/sdk-reference.md)에 있습니다. Python에서 와이어 예산은 `connect_array(..., wire_ceiling_mbps=120)`이며, 활성 데이터의 손상/미수신 구분은 [`/api/camera/array/<id>/capability`](../reference/sdk-reference.md#array-health--which-subsystem-is-losing-frames)에 나와 있습니다.
