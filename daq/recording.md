# 기록 및 .daq 형식

`.daq` 파일은 Chloros

의 광센서 기록 형식으로, 하나의 DAQ 센서에서 수집된 보정된 스펙트럼 프레임으로 구성된 **SQLite 데이터베이스**입니다. 캡처 세션 중에 하나를 기록해 두면, 반사율 파이프라인이 나중에 모든 이미지를 정확히 그 순간에 측정된 하향 복사조도로 나눌 수 있습니다.

## .daq 파일의 구성 요소

| 속성 | 값 |
| --- | --- |
| 컨테이너 | SQLite 데이터베이스, 기록당 센서당 하나의 파일 |
| 파일명 | **센서 ID**와**타임스탬프**를 포함합니다(예: `daq_data_daq-e-def330_2026_04_13_18h30m00.daq`) |
| 프레임당 스펙트럼 | 135개 데이터 포인트, 5 nm 간격으로 340–1010 nm 범위, CIE XYZ 삼자극 값 포함 |
| 단위 | 보정된 스펙트럼 조도, **W/m²/nm** (공장 보정 번들 + 캡 프로파일 적용) |
| 기록된 메타데이터 | 센서 ID(해당 장치의 공장 보정 데이터를 불러오는 데 사용되는 키) 및 적용된 캡 프로파일 — [캡 프로파일 및 보정 범위](caps-and-range.md) 참조 |

이 형식은 DAQ-U, DAQ-M, DAQ-E 및 DAQ-E-S에서 모두 동일하므로, 후속 처리 단계에서는 어떤 전송 장치가 기록했는지 상관없습니다. 또한 DAQ-E-S 기록에는 각 스펙트럼 옆에 장치의 틸트, 롤, 피치 각도도 저장됩니다.

**녹화 데이터는 정전 시에도 유지됩니다(1.3.0).**실시간 녹화 데이터는 매 커밋 시 저널과 전체 디스크 동기화를 통해 기록되므로, 정전이나 프로세스 강제 종료 시에도 파일 자체는 손실되지 않고 약 3초 분량의 데이터만 손실됩니다. 쓰기 도중 중단된 기록의 경우, `.daq` 파일 옆에 `<name>.daq-journal` 파일이 남을 수 있습니다:**두 파일을 모두 보관하고 함께 복사하십시오.** Chloros

는 파일을 처음 읽을 때 저널을 롤백합니다. 디스크가 바쁜 경우 파일 처리가 지연될 수는 있지만, 센서 측정값의 전송은 절대 지연되지 않습니다.

**데이터 전송이 중단된 DAQ-E는 다시 연결됩니다(1.3.0).** DAQ-E의 스트림이 중단될 경우(스위치 전원 재시작, 링크 끊김 등), 백엔드는 이전 설정을 유지한 채 다시 연결하며, 해당 DAQ-E의 기록은 파일 내에 간격이 표시된 상태로 동일한 `.daq` 파일에서 계속됩니다.

보정된 기록을 위해서는 센서의 공장 보정 번들이 필요합니다. DAQ-U 및 DAQ-M의 경우, 백엔드는 센서 ID를 기반으로 MAPIR

클라우드에서 번들을 가져옵니다(번들을 가져올 수 없는 경우 기록이 거부됨). DAQ-E 장치는 기기에 보정 정보를 저장하고 있으므로 이 규칙에서 제외됩니다.

## GUI를 통한 기록

GUI에서 녹화를 하려면 **열린 프로젝트**가 필요합니다(그렇지 않으면 녹화 버튼이 비활성화됩니다):

* **모두 녹화 / 모두 중지** — 광 센서 사이드바 상단; 연결된 모든 센서에 대한 `.daq` 녹화를 한 번에 시작하거나 중지합니다.
* **기록 / 기록 중지** — 센서별로, 톱니바퀴 설정 모달에서 사용할 수 있습니다. 기록 중에는 센서의 실시간 정보 행에 빨간색 &quot;REC&quot; 표시기가 나타납니다.

파일은 `<project>/light_sensor/`에 기록되며, 녹화가 중지되면(중지, 모두 중지, 또는 녹화 센서 분리 등 어떤 방식으로든) 완료된 `.daq` 파일이 **열려 있는 프로젝트에 자동으로 추가**됩니다. 이 파일은 수동 추가 단계 없이 프로젝트의 파일 목록에 표시되며, 반사율 처리를 위해 이미 준비된 상태입니다.

## CLI

를 통한 기록

CLI

는 백엔드의 센서 풀을 통해 기록합니다(백엔드가 실행 중이어야 함 — 이 명령어들은 경량 HTTP

클라이언트입니다):

```bash
# Connect the sensor into the backend pool
chloros-cli daq pool-connect --eth-host daq-e-def330.local

# Record for 150 seconds, with a human-friendly device label
chloros-cli daq pool-record --sensor-id daq-e-def330 --duration 150 \
    -o ./out --device-name "rooftop-A"

# Or run open-ended and stop explicitly
chloros-cli daq pool-record --sensor-id daq-e-def330            # --duration defaults to 0 = run until --stop
chloros-cli daq pool-record --sensor-id daq-e-def330 --stop
```

`--sensor-id` 값을 `chloros-cli daq pool-list`에서 가져옵니다. 알아두면 좋은 두 가지 기본값:

| 옵션 | 기본값 |
| --- | --- |
| `--duration` | `0` — `pool-record --stop`까지 기록 |
| `--output` / `-o` | `~/Documents/DAQ Live View/` (CLI

가 아닌 **백엔드**의 파일 시스템에 저장) |

CLI

가 다른 컴퓨터에 있는 백엔드를 대상으로 할 때 출력 디렉터리의 구분이 중요합니다. 파일은 백엔드가 실행되는 위치에 저장됩니다. 백엔드가 같은 컴퓨터에 있는 경우, 상대 경로인 `-o`(위의 `./out`와 같은)는 명령을 실행한 폴더를 기준으로 해석됩니다.

## Python

에서 녹화 `DAQSensorSession`(`chloros_sdk.connect_daq_sensor()`에 의해 반환됨)는 동일한 풀링된 녹화 데이터를 노출합니다: `record_start(output_dir=None, device_name=None)`는 파일 경로를 반환하고, `record_stop()`는 `{path, rows}`를 반환합니다. 전체 세션 API

에 대해서는 [SDK

참조](../reference/sdk-reference.md)를 참조하십시오. SDK

의 직접 하드웨어 클래스(데스크톱 설치용만 해당)는 기본적으로 `~/Documents/DAQ/`에 녹화 데이터를 기록합니다. 릴리스된 빌드의 경우, 위에서 언급한 풀링된 경로가 지원되는 방법입니다.

## 처리 시 .daq 파일 사용

이미지에서 반사율을 산출하기 위해, Chloros

는 각 노출에 일치하는 하향 복사량을 필요로 합니다:

* **`.daq` 파일을 이미지와 함께 보관하십시오.** 처리 시 파이프라인은 기록된 `.daq`(모든 DAQ 모델) 또는 이미지와 함께 있는 DAQ-M 네이티브 `.csv` —를 통해 자동으로 해결합니다. GUI 녹화 파일은 녹화가 종료되는 즉시 프로젝트에 추가되므로 이 조건이 자동으로 충족됩니다.
* **보정은 필요에 따라 불러옵니다.** 카메라별 또는 DAQ별 공장 보정 번들이 로컬에 아직 캐시되어 있지 않은 경우, Chloros

는 첫 사용 시 MAPIR

의 클라우드에서 이를 자동으로 가져옵니다(인터넷 연결이 한 번 필요하며, `~/.chloros/`로 캐시됨).
* **실시간 캡처는 자체 사이드카 파일을 작성합니다.** 라이브로 캡처된 모든 반사율 프레임의 경우, 실제로 사용된 DAQ 측정값이 캡처 파일의 `daq/` 폴더 내에 `.daq` 파일로 저장되므로, 원본 녹화 파일 없이도 나중에 캡처 데이터를 재처리할 수 있습니다.
* **`chloros_scripts` 레코더(1.3.0)의 녹화 파일.**공개용 [`chloros_scripts`](https://github.com/mapircamera/chloros_scripts) 레코더가 생성한 `.daq` 파일은 이를 생성한 DAQ 모델로 표시되며, 해당 캡은 다른 기록과 마찬가지로**프로젝트 설정 → DAQ 광 센서**에서 다른 녹화 파일과 마찬가지로 설정할 수 있습니다. 해당 레코더는 센서의 원시 카운트 값을 기록하며, Chloros

는 시리얼 통신을 통해 센서의 공장 보정 값을 가져와 적용합니다.
* **측정값의 출처 (1.3.0).**각 캡처 항목인 `.daq` 옆에는 `.daq.cameras.json`라는 이름이 표시되며, 이는 해당 측정값이 설명하는 프레임을 촬영한 카메라를 나타내며, 처리는**해당 카메라에서 촬영된 이미지에만** 적용됩니다. 따라서 자체 광 센서가 없는 독립형 카메라는 더 이상 다른 카메라의 측정값을 차용하지 않습니다. 센서를 해당 카메라에 바인딩하거나 직접 기록해야 합니다. DAQ 자체로 생성된 녹화 파일(GUI 녹화, `daq pool-record`)과 해당 파일이 포함되지 않은 모든 `.daq` 파일(구버전 캡처 포함)은 여전히 모든 카메라에 적용됩니다.

## 조도 데이터 다시 추출하기

프로젝트를 처리하면 해당 프로젝트에 포함된 모든 광센서 기록 데이터가 이미지 결과물 옆의
`Light Sensor/` 폴더로 내보냅니다. 이때 **이미지**는 필요하지 않습니다.
빛 센서 기록만으로도 완전한 캡처가 되며, `.daq`
파일만 포함된 폴더도 유효한 입력입니다. 광센서 기록만 포함된 프로젝트는 앱과 CLI

모두에서 해당 항목을 나열하고
처리하며, 실행 후에도 목록에 남아 있습니다. 실행 결과
보고서에는 작성된 광센서 산출물의 수가 표시됩니다.

| 산출물 | 설명 |
| --- | --- |
| `<name>_calibrated.daq` | 실시간 기록과 동일한 스키마를 따르는 재처리 가능한 아카이브로, 이를 생성한 보정 번들을 명시합니다. 이를 다시 가져와도 **두 번째** 보정은 수행되지 않습니다. |
| `<name>_calibrated.csv` | 센서 고유의 파장 그리드에서 W/m²/nm 단위의 스펙트럼 조도. 각 측정값마다 한 행씩 기록되며, 총 전력, 광시 및 암시 럭스, 청색/녹색/적색 분할이 포함된 PPFD, 피크 파장 등의 광도학적 열이 포함됩니다. |

교정 번들을 가져올 수 없는 DAQ-U 또는 DAQ-M(오프라인 상태이거나
해당 센서의 교정 파일이 없는 경우)은 **사유를 명시하여 건너뛰며**, 원시 카운트 값을 포함하는
&quot;교정된&quot; 파일로 절대 출력되지 않습니다. 인터넷에 연결한 후 다시 실행하십시오. DAQ-E는
자체 교정 정보를 보유하고 있으므로, 장치가 연결되어 있지 않고
로컬에 캐시된 데이터가 없을 때만 이 절차가 필요합니다.

### DAQ-A: 원시 카운트, 그리고 이것이 올바른 이유

**DAQ-A**는 시리얼별 보정 번들 시스템이 도입되기 이전에 출시된 모델로, 가져올
번들이 없습니다. 이는 실수가 아닙니다. DAQ-A는 현장에서
반사율 타겟을 기준으로 보정되며, 타겟 기반 보정에는 센서의 *상대적*
응답만 필요하기 때문입니다. 이는 바로 원시 카운트 값 그 자체입니다. Chloros

는 현재도 이를 사용하여 보정하고 있습니다.

따라서 DAQ-A 기록 데이터는 내보내지지만, 다른 이름으로 저장됩니다:

```
<project>/
└── Light Sensor/
    ├── <name>_raw.daq
    └── <name>_raw.csv
```

`_raw`, `_calibrated`가 아닙니다. 파일 내부의 플래그가 아니라 별도의 파일 이름을 사용하는 이유는,
파일이 단순한 파일명으로 이메일로 전송될 때도 해당 정보가 유지되어야 하기 때문입니다. `.csv`
헤더에는 `raw spectral sensor counts (NOT irradiance)`라고 표시되어 있으며, 이 값들은
파일 **내부**에서만 비교 가능하고 센서 간에는 비교할 수 없다는 경고가 있습니다. 실제 조도(총 전력, 럭스, PPFD)에 대해서만
의미를 갖는 열은 카운트 값을 바탕으로
계산하지 않고 비워 둡니다.

구형 DAQ-A-SD 기록 파일(스키마 v1.01 / v1.02)은 파일의 쓰기 시간만 기록하며,
각 측정값별 타임스탬프는 기록하지 않습니다. Chloros

는 이러한 기록과 이미지를 매칭하지 않습니다 — 프레임을
쓰기 시간과 연결하는 것은 겉보기에는 문제가 없어 보일지라도 잘못된 방법입니다 — 하지만 내보내기 기능은 이를 정상적으로 읽으며
CSV

파일에는 해당 기록이 어느 클럭에 속하는지 명시되어 있습니다.

반사율에 대한 전체 내용 — 카메라를 사용한 단일 센서 방식 및 주변광/피사체용 듀얼 센서 방식 — 은 [반사율 워크플로우](reflectance.md)를 참조하십시오.
